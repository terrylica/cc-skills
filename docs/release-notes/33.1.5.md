## v33.1.5 — 2026-10-02

v33.1.5 fixes two bugs. The first was user-visible: the scheduled Gmail digest arrived in Telegram with literal `**` and `#` characters. The digest runs in a private Restate deployment, which now imports this plugin's `markdownToTelegramHtml` so that the digest and the bot's agent router share one converter. That converter had two faults of its own. It inserted HTML tags into text it had not escaped, so a single `<` or `&` in an email subject made Telegram reject the whole message. Its underscore-italic rule also mangled snake_case names, email addresses and URLs. Both are fixed, and the converter now also handles headings and bullets. The second fix is in the test suite: the pre-push gate could fail on a proto shim test even though proto was fine, because the variable that pins the bun version leaked from the gate's own process into the test.

### Fixed

- **gmail-commander `markdownToTelegramHtml`** (91699a38):
  - Code spans and links are set aside first, all remaining text is HTML-escaped, and only then is formatting applied, so a `<` or `&` in an email can no longer get the message rejected by Telegram.
  - `# Heading` lines become bold lines, because Telegram HTML has no heading element.
  - `-`, `*` and `+` bullets become `•`, with indentation kept.
  - Underscore and single-asterisk italics apply only at word boundaries, so snake_case names, emails and URLs are left alone.
  - Every tag opens and closes on one line, so splitting a long message on newlines never leaves a tag unbalanced.
  - 11 new tests in `telegram-format.test.ts`.
- **Proto shim test, case 3** (3450eed0): the test no longer inherits `PROTO_BUN_VERSION`. The pre-push gate starts moon through `bun gate-slot.ts`, and the bun shim exports that variable to every child, where it overrode the test's `.prototools`. The "missing tool" shim therefore ran the installed bun and exited 0. That looked like the moonrepo/proto#1105 failure class returning, but it happened only inside `git push`.

### Changed

- **`formatForTelegram` removed**: `markdownToTelegramHtml` now escapes plain text itself, so the wrapper's "has Markdown?" branch had nothing left to choose between. The agent router calls the converter directly.
- **Case 3 now asserts STDERR**: moonrepo/proto#1110 was closed on 2026-09-10 (fixed in v0.61.3, below the pinned 0.62.3). A missing-tool failure is now required to report on STDERR, where previously this was only noted in the output. On 0.62.3 it measured 0 B on stdout and 381 B on stderr.
