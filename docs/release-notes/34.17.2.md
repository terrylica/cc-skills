## [34.17.2](https://github.com/terrylica/cc-skills/compare/v34.17.1...v34.17.2) (2026-11-15)

This patch makes FloatingClock's input level meter move while a dictation app records AirPods on macOS 26. The meter joins a Bluetooth microphone only while someone else is already recording it, so the clock never pushes a headset into call mode itself. It used to learn that from the list of processes recording each device. On macOS 26 a dictation app can instead use Apple's hosted voice processing, which runs the microphone inside the audio daemon. A dictation into AirPods then showed no recording process at all, and the meter stayed dark. The clock now also joins when the input device itself reports it is in use and nobody is listed, but only for an input-only device, so music playing to the same headset can never trigger it. While joined, it briefly pauses its own capture every five seconds to check that someone else still holds the microphone, and a single join is capped at ten minutes.

### Summary

- **floating-clock, level meter** ([#99](https://github.com/terrylica/cc-skills/pull/99), closes [#98](https://github.com/terrylica/cc-skills/issues/98)).
  - **New signal:** joins a Bluetooth input when the device is running somewhere with no process listed. This applies to input-only devices only; AirPods expose input separately from playback.
  - **Leaving a join:** while joined, the clock stops its own capture every 5 s, waits 300 ms and reads the flag again: still running means someone else holds it, so it rejoins; otherwise it stays off.
  - **Safety cap:** a hosted join lasts at most 10 minutes, then the meter stays off for 3 s whatever the flag says, so a lagging flag can never latch call mode on.
  - **Verified live with AirPods:** two dictations of about 20 s. The meter read speech at 0.15 to 0.31 RMS and stopped within a second of each recorder.
- **Unchanged:** the exact path (a listed recorder) behaves as before.
- **Tests:** 156 pass; the audio layer stays outside the unit-test link.
