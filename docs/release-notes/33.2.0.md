## v33.2.0 — 2026-10-02

v33.2.0 removes a workaround that was part of every marketplace hook and replaces the silent protection it gave with an explicit check. Since 2026-08-30, each of the 36 hook commands started with `env -u AI_AGENT -u CLAUDECODE`, to stop proto from writing to stdout when it detects an agent environment. Proto has now fixed both problems that made this necessary: the stdout banner (moonrepo/proto#1105, fixed in 0.61.2) and failures that went to stdout instead of stderr (moonrepo/proto#1110, fixed in 0.61.3). The repo's own measurement confirms it: a hook command without the prefix, whose pinned bun is missing, now exits 1 and names the cause on stderr. Removing the prefix still leaves one gap. Hooks run under each machine's own proto, so a machine on an older proto would have hook decisions discarded with no sign. Instead of keeping a prefix that hides that, this release adds a proto version floor, checked at session start and by `itp-hooks:setup`.

### Added

- **Proto floor check** (`plugins/itp-hooks/scripts/proto-floor.sh`): one plain-bash check. It passes when `bun` is not a proto shim, or when proto is 0.61.3 or newer. It returns 1 when proto is below the floor and 2 when proto's version cannot be read.
- **SessionStart hook** (`sessionstart-proto-floor-check.sh`): when the floor fails, it adds a one-line warning to the session's context. It stays silent otherwise and never blocks. It is written in bash so that it does not itself run through the shim it checks.
- **Setup enforcement**: `install-dependencies.sh --check`, used by `itp-hooks:setup`, counts a failed floor as a missing required dependency.
- **Regression test** (`tasks/tests/test-itp-hooks-proto-floor.sh`): 8 cases with fake shim homes. They cover proto at the floor, below it, unreadable, and a bun that is not a proto shim, plus what the SessionStart hook prints in each case.

### Removed

- **The `env -u AI_AGENT -u CLAUDECODE` prefix** from all 36 hook commands across 7 plugins (calcom-commander, devops-tools, gh-tools, itp-hooks, productivity-tools, rust-tools, statusline-tools).
- **The `validate-plugins.mjs` lint that required the prefix**, together with the helpers only it used (`PROTO_SHIMMED_TOOLS`, `AGENT_ENV_STRIP_PREFIX`, `shebangInterpreter`).

### Changed

- **Hook-command parsing still accepts `env` wrappers.** User settings and older installed plugin versions still carry the prefix, so the parser and its fixtures are unchanged. Comments that called the prefix "load-bearing" now describe it as history.
- **`docs/LESSONS.md`**: a new entry dated 2026-10-02 records the re-measurement, and why a test that pins a tool version through `.prototools` must unset `PROTO_<TOOL>_VERSION`.
