## [33.22.0](https://github.com/terrylica/cc-skills/compare/v33.21.1...v33.22.0) (2026-10-20)

Some Google Workspace settings exist only in the Admin console: Gmail Default routing, for example, is absent from the Cloud Identity Policy API's supported settings, and GAM cannot set it. This release adds a new plugin, gws-admin-console, that drives such pages through your own signed-in Chrome profile (via the chrome-profiles plugin's Playwright Extension route) and treats each setting as a recipe: flags become form operations, the form is read back before Save, and after Save the page is reloaded and the stored rule is compared field by field. The result is that a console-only setting learned once can be applied again for any tenant from one recorded command, idempotently, and proven rather than assumed.

### Added

* **gws-admin-console:** harness for console-only Google Admin settings ([1f3af20](https://github.com/terrylica/cc-skills/commit/1f3af20464863aa22effb52acde1f08c57e3e4e3))

- New plugin gws-admin-console with skill admin-console and the CLI scripts/gws-admin-console.ts (recipes, `<recipe> <verb>`, serve, stop; `--help` and `recipes --json` describe every flag and exit code).
- Recipes are data: flags become a list of form operations (select, pick, tick, fill, choose) replayed one step at a time, with a read-back before Save and a field-by-field comparison of the rule's Edit dialog after a fresh reload (exit 1 on mismatch).
- First recipe `gmail-default-routing ensure`: match group, single, pattern or all; change the envelope recipient; add X-Gm-Original-To; recognized or non-recognized scope. Identical rule is a no-op, a differing one is reported (exit 3) unless `--update`; `--dry-run` fills and cancels; `--verify` only reads back.
- Re-authentication gate: a "verify it's you" page is detected, the operator is alerted (local notice, optionally a Pushover Emergency), the tab is polled and never reloaded, and no password is ever typed (exit 4 on timeout).
- Lessons measured live and baked into the primitives: force clicks after bringToFront in background tabs; a checkbox is found from its label's nearest checkbox-bearing ancestor; the Select Groups picker selects on a row click, has no confirm button and must be closed with its X; the rules table is lossy, so identity is read from each candidate's Edit dialog.
- `--screenshots <dir>` saves a PNG per step; any failed step is always captured, cancelled and reloaded so a half-filled rule is never saved.
- 39 unit tests cover flag parsing, run-code result parsing, page classification, spec parsing, form planning, form read-back, diffing and table parsing, with fixtures anonymised to example.com.
