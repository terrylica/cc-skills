## [34.4.0](https://github.com/terrylica/cc-skills/compare/v34.3.1...v34.4.0) (2026-10-23)

This release makes quoting someone in an email draft a first-class part of the gmail-commander draft builder. A reply that answers several points reads best when each of the other person's passages is quoted exactly and answered underneath. Until now a `>` line arrived in the recipient's inbox looking like any other paragraph, with a literal "&gt;" in front of it. Now the builder recognises a block whose every line starts with `>` as a quotation. It renders it in its own colour, italic, with a bar down the left, and keeps the plain-text `>` convention in the text part. The gmail-access skill now states the convention: quote verbatim, one block per passage, reply outside the block. The release also fixes a memory leak in chrome-profiles' `mcp-drive`, which left one Chrome tab open per run.

### Summary

- **gmail-commander:** a block whose every line starts with `>` (up to three spaces of indent) is a quotation; the HTML part renders it as a `<blockquote>` styled inline with `QUOTE_BLOCK_STYLE` (Gmail drops `<style>` blocks), and the plain-text part keeps the `>` prefix.
- **gmail-commander:** a stray `>` inside prose (an arrow, a comparison) stays prose; only a block where every line carries the marker counts.
- **gmail-commander:** the forced-line-break check now also covers `<blockquote>` and tags that carry attributes, so a hard-wrapped quotation is refused like a hard-wrapped paragraph.
- **gmail-commander:** the gmail-access skill documents the convention: quote verbatim, one `>` block per passage, the reply outside it, never hand-styled HTML.
- **chrome-profiles:** `mcp-drive` closes the tab each extension-mode run opens (a long session had piled up 8.7 GB across 70 renderers); `MCP_DRIVE_KEEP_TAB=1` keeps it, for example while a download it started is still writing.
- Five new builder tests (97 in total) cover splitting, indent rules, plain and HTML rendering, and MIME validation with a quotation.
