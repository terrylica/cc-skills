## v32.3.0 — 2026-09-27

v32.3.0 closes out one day's work putting Claude Code's kernel sandbox in front of agent commands, and then standing it down. It ships the last pieces built for the sandbox — a pass/fail regression check for the managed sandbox policy and a one-folder Apple Notes broker so `draft-park` could run from a sandboxed session — together with `--uninstall`, which removes the managed sandbox policy from a host, and a broader kill guard built for the sessions and hosts the sandbox does not cover. The operator ruled the same day that the sandbox blocked too much autonomous work (ps, log, sysctl, launchctl, osascript, git over the ssh alias, and writes under `~/.claude`, including this release's own plugin sync and post-release step, although its tag and GitHub release were published from inside the sandbox), and the policy was uninstalled that afternoon from all four hosts it had been installed on. The commit after this release ([aa639eb](https://github.com/terrylica/cc-skills/commit/aa639eb982788bf26002d59c6d21d3cf59ca3c52)) retires the policy from the repository altogether; it stays recoverable from the tag `archive/pre-retire-managed-sandbox-policy`.

What that means for a consumer: the current Notes path is direct `osascript`, as before. `draft-park` uses the broker only when `SANDBOX_RUNTIME` is set and `host-notes` is installed, or when `DRAFT_PARK_BACKEND=broker` forces it. The kill guards are ordinary plugin hooks and stay in force either way.

Two changes are worth knowing even without a sandbox. One was found on the broker's first live use: `htmlToText()` used to return an empty string when its converter produced nothing, so a failed conversion could hand a human blank text to send; it now throws `HtmlToTextError` whenever the converter exits non-zero or returns nothing for a note that has visible text, on every host. The other was found while cutting this release: the hook-suite benchmark cases that failed three of the operator's five release attempts that day (the other two stopped earlier, on a dirty working tree) now print the benchmark's own output when they fail, because until now the reason was discarded twice.

### Added

- `install_managed_sandbox_policy.py --uninstall [--apply]` unloads and removes the diagnostics broker and its plist (macOS) or the `/etc/apparmor.d/bwrap` profile (Linux), every script and runner the installer placed under `/usr/local/libexec/claude-code-sandbox-policy`, and `managed-settings.json`; without `--apply` it previews exactly what would go ([071418c](https://github.com/terrylica/cc-skills/commit/071418cad187f1e3c5bd75e275e5805bdf4c8908)).
- Kill guard v2, `pretooluse-broad-process-signal-guard`: denies `kill -1`/`kill 0` as a target (`kill -1 <pid>`, a SIGHUP, stays allowed), `pkill`/`killall` of shared runtimes and host programs by name (such as node, bun, python, claude, shells, ssh, iTerm2, tmux, Chrome, launchd and systemd) including `kill $(pgrep node)`, a user-wide `-u` with no process name, and `pkill` patterns under five literal characters, in Bash commands and in shell scripts written with Write/Edit/MultiEdit; escape `BROAD-PROCESS-SIGNAL-OK` ([f5b8d90](https://github.com/terrylica/cc-skills/commit/f5b8d90ddab9ec4c0735d2b31320e381635d53c9)).
- `verify_managed_sandbox_policy.py` (moon task `repo:sandbox-policy-verify`): a change-nothing pass/fail check of an installed policy, with a static tier and an opt-in `--live` tier ([bdb854c](https://github.com/terrylica/cc-skills/commit/bdb854c51cbb514b42a038cd518b557282d636dd)).
- Apple Notes drafts broker and `host-notes` client, confined to the `Claude Drafts` folder (list, read, create, replace; no delete) and checking folder membership with `id of notes of folder` after the first form failed `-1728` in pre-release live use, plus a fixed-argv `textutil` endpoint (`host-notes html2txt`) because `textutil` writes nothing inside the sandbox and still exits 0; every request must name the broker in its Host header and every POST must carry `X-Sandbox-Broker: 1` ([e9b184e](https://github.com/terrylica/cc-skills/commit/e9b184e68b8de6528250094d4900ea7faa04fd5a), [8d951de](https://github.com/terrylica/cc-skills/commit/8d951de86a699212e56e22fdd6766b6c97d9ac5e), [b1abe9f](https://github.com/terrylica/cc-skills/commit/b1abe9f91c31619657b830eb555f0cc0eed21f28)).
- `draft-park` selects the broker when `SANDBOX_RUNTIME` is set and `host-notes` is installed (`DRAFT_PARK_BACKEND=osascript|broker` forces either), updates a re-parked title in place because the broker cannot delete, and stops with the install command when sandboxed without `host-notes` ([4c92882](https://github.com/terrylica/cc-skills/commit/4c9288267c46f19b25e4bdce2e7717db509aa863)).

### Changed

- The sandbox escape gate refuses escaped `osascript` and points to `host-notes`, because an escaped Notes call failed `-10810` exactly as a sandboxed one did; its deny text also says that on macOS the escape flag changes nothing for `git`, which a peer session measured three times (Linux is unmeasured, so the gate's `git` verdicts are unchanged) ([e9b184e](https://github.com/terrylica/cc-skills/commit/e9b184e68b8de6528250094d4900ea7faa04fd5a)).
- The iter94 and iter95 hook-suite benchmarks keep `bun`'s stderr, and their tests print the benchmark's last 25 lines on failure ([934cc7d](https://github.com/terrylica/cc-skills/commit/934cc7df5a3eaee1c7c7d704d33045a2d8187bdc)).

### Fixed

- `htmlToText()` no longer returns an empty string when conversion fails for a note with text; it throws `HtmlToTextError` with the reason, and `draft-park` exits cleanly on it ([b1abe9f](https://github.com/terrylica/cc-skills/commit/b1abe9f91c31619657b830eb555f0cc0eed21f28)).
- The load-average sample falls back to `uptime` where `sysctl` is refused ([31d0ab3](https://github.com/terrylica/cc-skills/commit/31d0ab31c2d9966b73692b38788b4fd477d992b3)).
- The unit suites no longer touch the live review-round store (`ITP_HOOKS_REVIEW_ROUND_STATE_ROOT` points them at a throwaway directory), and the two tests that need `ps` skip with their reason where it cannot run ([54ae027](https://github.com/terrylica/cc-skills/commit/54ae027901a61d76c0aa1f0ebb6ce09b31940b4b)).
- `ssh-tunnel-companion` drops its dead `:18082` and `:5900` forwards and now forwards only `18123` and `18081` ([db0aa28](https://github.com/terrylica/cc-skills/commit/db0aa28fa05b782aef890d189e6365fe1e63ce25)).

### Upgrade notes

- `ssh-tunnel-companion`: the forward change takes effect on the next tunnel restart (`make restart` or `launchctl kickstart -k`).
- Removing the managed sandbox policy from a host: run the uninstaller from this release's tag, because [aa639eb](https://github.com/terrylica/cc-skills/commit/aa639eb982788bf26002d59c6d21d3cf59ca3c52) deletes its directory from `main` — `git show v32.3.0:plugins/itp-hooks/managed-sandbox-policy/install_managed_sandbox_policy.py > /tmp/install_managed_sandbox_policy.py && sudo /usr/bin/python3 /tmp/install_managed_sandbox_policy.py --uninstall --apply` — then restart every open Claude Code session. A session started under the policy keeps its `PreToolUse` gate registered, and once the gate's script is deleted every Bash call in that session fails until it restarts.
- On a host where the installer ran more than once, the uninstall leaves its timestamped `.bak-*` backups behind (five on the Mac that cut this release), so `/usr/local/libexec/claude-code-sandbox-policy/` survives as a directory of inert files.
