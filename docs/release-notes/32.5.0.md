## v32.5.0 — 2026-09-30

v32.5.0 settles how automation should sign in to websites, following what agent platforms such as Browserbase, Steel and Kernel, and password managers such as 1Password, now recommend. The `chrome-profiles` skill adds a new top rung, an API or OAuth token, so work that a site's API can do never opens a browser. Unattended work runs in a profile of its own that holds only the one site it needs, so a mistake or a hostile page can reach that site and nothing else. Your real everyday profile, which carries every session you have, is reserved for work you are watching. When a tool's own session expires, the new `fill-secret.mjs` types the password from your macOS Keychain or vault into the login field, and the AI driving the browser never sees it.

### Added

- `chrome-profiles/scripts/fill-secret.mjs`: types a Keychain (`--keychain service:account`) or vault (`--vault scope:key`) secret into exactly one field of exactly one tab on a debug-port Chrome, optionally submitting the form, and prints only a character count. It uses Node's built-in fetch and WebSocket and has no dependencies.
- It refuses a field too short for the secret (a truncated password would be saved without any error), a selector that matches anything other than exactly one input, and a missing secret. All of these, plus fill-and-submit, were tested end to end on a throwaway profile with a throwaway Keychain item.

### Changed

- The `browser-automation` skill's ladder gains rung 0, an API or OAuth token, ahead of plain HTTP; rung 2 now also covers the per-tool, sign-in-once profiles.
- New "Who signs in, and how" rules: unattended work never runs in your real profile; your real profile is for supervised work; expired logins are refilled by `fill-secret.mjs`, never typed by the AI.
- The README now lists Node 22+ as a requirement.
