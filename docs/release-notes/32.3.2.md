## v32.3.2 — 2026-09-27

v32.3.2 makes a Notes backup say whether it is complete. A real export of 637 notes, run to check v32.3.1, skipped one note because `textutil` had been killed by a signal once in over 600 conversions; the same note converted 80 of 80 times on its own. Before v32.3.1 that death put the note into the backup as an empty file with no warning, and in v32.3.1 the skip was loud on screen but `manifest.json` still listed only the notes it wrote. The manifest now records `complete` and every skipped folder and note with its reason, and a crashed conversion is retried once. The same release makes the orchestrator subhook audit fail under `--strict` when it finds nothing to check, and has the two hook tests that failed under parallel load today record why the audit stopped.

### Fixed

- `notes export`: `manifest.json` gains `complete` (false when anything was skipped) and `skipped.folders` / `skipped.notes`, each with a reason; existing fields are unchanged ([7e37dcb](https://github.com/terrylica/cc-skills/commit/7e37dcbb23128048290410aee43038bf03563c11)).
- `htmlToText()` makes two attempts, except on `ENOBUFS`, and a killed run is reported as `killed by <signal>` instead of `exit null` ([7e37dcb](https://github.com/terrylica/cc-skills/commit/7e37dcbb23128048290410aee43038bf03563c11)).
- The orchestrator subhook contract audit exits 1 under `--strict` when it discovers no subhook files, where it used to report a clean gate on zero files; informational mode still exits 0 ([dc17322](https://github.com/terrylica/cc-skills/commit/dc1732207520419f9c479308fe2ed6737d42a96e)).
- The iter86 and iter88 hook tests record the audit's exit status and print it on failure, so the next load-dependent failure names its cause ([dc17322](https://github.com/terrylica/cc-skills/commit/dc1732207520419f9c479308fe2ed6737d42a96e)).

### Upgrade notes

- Anything that treats a notes-export snapshot as a backup should check `manifest.json` `complete` (or exit code 3), not only that the manifest exists.
- A second full export after the fix returned 638 notes with `complete: true` and exit 0, including the note the first run skipped.
