## v33.15.0 — 2026-10-15

v33.15.0 gives FloatingClock two new rails. The first shows live sound levels. A thin strip between the clock and the audio I/O bar shows LED-style meters for what the default input hears and for what the Mac is playing, each lined up under its own half of the audio bar. macOS has no property for the current output level, so the output half uses a Core Audio process tap (macOS 14.2+). The tap runs only while another app is actually playing, so the purple "system audio recording" dot appears only then, and coreaudiod is not kept awake during silence. The second rail is a generic watched-USB-device rail. From the IOPort registry, read in-process, it shows whether a chosen device is docked, off its dock, or whether the dock is unplugged. It also shows what an external job is doing with that device (phase, progress, rate, outcome), read from a small JSON status file the job writes. The plugin knows nothing about any particular device or job: the IDs, the label and the status-file path are preferences. Both rails are off by default. To fit rails of different heights into the middle of the stack, the overlays now share a small stack registry instead of each rail listing the rails below it.

### Added

- **Level-meter rail** (`b95492ab`, floating-clock): green cells for input, blue for output, amber above -12 dBFS and red above -3 dBFS, and a 1 s peak-hold tick. Input reuses the mic-mute indicator's existing IOProc, so there is no second capture; Bluetooth inputs stay unmetered. The 24 Hz animation runs only while there is signal, and frames that change no cell skip Core Animation. Keys `LevelMeterEnabled` and `LevelMeterOutputEnabled`; menu item "Show Level Meters".
- **Output level tap** (`b95492ab`, floating-clock): a private, global, unmuted process tap inside a private aggregate device. Playback is unaffected. It is rebuilt when the default output or its sample rate changes, and `AudioDeviceStart` runs off the main thread because it can block on the one-time "System Audio Recording Only" prompt (`NSAudioCaptureUsageDescription`).
- **Device rail** (`b95492ab`, floating-clock): four dock states (`●` docked, `◌` off dock, `○` dock unplugged, `?` not seen yet) from the port the device last enumerated on, plus a `↻` mark when the device drops and comes back within 10 s. Job progress uses a `◐◓◑◒` spinner and an eighth-block bar at 4 Hz, only while the job's process is alive. A job that died mid-run reads `⚠ stopped during <phase>`. Keys `DeviceRailEnabled`, `DeviceRailVendorID`, `DeviceRailProductID`, `DeviceRailLabel` and `DeviceRailStatusFile`.
- **Overlay stack registry** (`b95492ab`, floating-clock): `FCOverlayStack` registers rails by order and height. Each existing rail now adds one call for the registered height below it, instead of every rail learning about every newcomer.
- **Tests** (`b95492ab`, floating-clock): 10 new unit tests cover the dB mapping, the release and peak-hold ballistics, the eighth-block bar, dock-state derivation, the status-file parser and the composed rail text. 143 tests pass.

### Documentation

- **Overlay indicators** (`b95492ab`, floating-clock): the stack order, the registry, both rails, their preference keys, the permission and privacy-dot behaviour, and the measured cost (about 0.8% CPU for the live meters while a microphone hears a room, and nothing measurable for the device rail).
