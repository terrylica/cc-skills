# [34.2.0](https://github.com/terrylica/cc-skills/compare/v34.1.1...v34.2.0) (2026-10-22)

This release finishes a cleanup pass across the marketplace and adds three operator-facing features. FloatingClock's audio bar, device menu and level-meter tap no longer query CoreAudio on the main thread, so a stalled coreaudiod can no longer freeze the clock through them (#39; the mic-mute indicator remains, tracked in #37). gmail-commander drafts can carry an authored HTML part that is checked against the plain text and a stricter blocklist before upload (#41); session-closeout waits for running subagents, teammates and background work before closing a tab (#42); and chrome-profiles setup reads the Playwright Extension token from the profile instead of asking for a paste (#47). On the removal side, about 3,500 lines of dead code, docs and ADRs are gone (#43), the Deflated Sharpe Ratio and every trial-count correction are removed from the quant-research skills while PSR, MinTRL and the non-IID variance stay (#45), and the CLAUDE.md files lose about 19 KB of stale facts, changelog narrative, duplicates and generic advice (#49). Supporting changes: TypeScript declared as latest in two plugin manifests and the proto pin realigned (#40), the pueue wrap hazard corpus ported to the current tests (#48), and process-bound tests in session-closeout given a load-proof timeout (#46, #50).


### Bug Fixes

* **floating-clock:** audio bar and level tap read the HAL off main ([7d42dbb](https://github.com/terrylica/cc-skills/commit/7d42dbbc37f9827d2828399e0f4722ebca96a15b)), closes [#25](https://github.com/terrylica/cc-skills/issues/25)
* **gmail-commander:** --html accepts named links; stricter blocklist ([7c68069](https://github.com/terrylica/cc-skills/commit/7c68069264ec61efc2d34dfb30fb575db05484bd)), closes [#24](https://github.com/terrylica/cc-skills/issues/24) [#x09](https://github.com/terrylica/cc-skills/issues/x09) [#31](https://github.com/terrylica/cc-skills/issues/31)
* **gmail-commander:** --html refuses a formaction attribute ([699f748](https://github.com/terrylica/cc-skills/commit/699f748c15f0e931e42c2900489454296922f2bf))

Before this change, --html accepted &lt;input type=image formaction="https://...">. Any formaction attribute is now refused, inside a form or not: it only matters as a form submit target, and a draft never submits anything.

* **orca-tools:** session-closeout watcher never hangs or leaves markers ([29d87bc](https://github.com/terrylica/cc-skills/commit/29d87bc56854e8feeac270571bc7b498701983fd)), closes [#30](https://github.com/terrylica/cc-skills/issues/30)

Every external call in orca-closeout (ps, lsof and every Orca CLI command, including terminal wait) now has a timeout, ORCA_CLOSEOUT_CALL_TIMEOUT seconds (default 20), and runs in its own process group so a timeout kills all of it. A call that times out counts as not confirmed: --close refuses up front, a hung lsof reads as a running command, and the watcher keeps waiting instead of closing.

The watcher removes the [running] tab prefix and the workspace markers on every way it ends: settled, --settle-timeout, the agent process gone, the tab no longer this session's, Orca never reporting the turn idle, or a signal. A tab with no label of ours is reset by omitting --title, which `orca terminal rename --help` documents as the reset to the automatic title. Orca has no way to unset a workspace status or comment, so each is marked only when it already had a value, and restored to exactly that value.

A second run while the first one's markers are on reads the originals from the first run's state file, so the comment never becomes "Running: … | Running: …" and in-progress is never recorded as the status to restore. The agent's start time comes from ps -o etime= under LC_ALL=C, not the localized lstart, so old launches are ignored under any locale. A typed prompt whose content is a list of blocks (an image or a pasted document) now cancels the close; tool results and list-form task notifications still do not.

The script's tests (49) already run in moon run repo:check, whose test task runs every tracked *.test.ts.



### Features

* **chrome-profiles:** setup reads the extension token from the profile ([4e6d798](https://github.com/terrylica/cc-skills/commit/4e6d798dd62b8245ab0827827f58d569391f65c5)), closes [#36](https://github.com/terrylica/cc-skills/issues/36)

`chrome-profile.sh setup` opened the extension's status page and then asked the operator to copy its token into a hidden dialog. The extension keeps that token in its own origin's localStorage under `auth-token`, so setup now reads it from the profile itself: it polls for up to 12 s after opening the status page, stores the token in the login Keychain through the existing `token_put` (`security -i`, hex on stdin), and falls back to the paste dialog with the reason (not written yet, no readable Local Storage, not token-shaped, bun missing) only when reading fails.

Recovered from an earlier set-aside draft (the only copy, referenced by the issue), whose reader was Python on `ccl_chromium_reader` fetched unpinned from GitHub at every run with `uv run --with git+https://...`, i.e. third-party code pulled fresh off the network and run against the directory that also holds the browser's cookies. The repo's default language is Bun/TypeScript and the formats involved are small and frozen, so the reader is now `extension-token-from-profile.ts`: a dependency-free LevelDB log + table reader with raw Snappy and CRC-32C, using only node: built-ins. No python-allowlist.toml entry is needed.

Secret handling: the reader never opens Chrome's live database; it copies every regular file except LOCK (symlinks not followed) into a mkdtemp directory chmod 0700 with 0600 files, retries when Chrome deletes a file mid-copy, and deletes the copy in a finally block and on SIGINT/SIGTERM/SIGHUP. The token leaves the process only on `--emit-fd N`, which refuses fds 0-2 and terminals; stdout carries a JSON status line with the length only, and stderr carries reasons and file names, never bytes. `token_from_profile` runs bun from the script's own directory with `--no-env-file --no-install --config=/dev/null`, so nothing in the caller's working directory is loaded.

Tests: `extension-token-from-profile.test.ts` (24 cases, in the marketplace bun suite) runs against fixtures written by real LevelDB through classic-level (`fixtures/extension-token/make-fixtures.mjs`, synthetic tokens only): token in the write-ahead log with the newest of two writes winning, in a Snappy-compressed table whose raw bytes do not contain it, UTF-16 values, another origin's token ignored, a deletion overriding a table value, a malformed value refused unprinted, no Local Storage, a torn log tail, a LOCK held by flock and chmod 000 with the live files hashed unchanged and the private copy removed, the snapshot's permissions, every refused `--emit-fd`, and the shell function extracted from chrome-profile.sh (found, not found, bun missing, a hostile .env and bunfig.toml in the caller's directory not loaded). Every case asserts that no fixture token reaches stdout or stderr.

The skill docs (SKILL.md, doctrine.md, README.md, CLAUDE.md) now describe setup without the paste step, and carry the stash's two other notes: never script a fresh debugging connection per command against the everyday Chrome, and why `claude --chrome` is no substitute behind a gateway.

The fixtures include LevelDB write-ahead `*.log` files, which the root `*.log` ignore rule would have dropped; `.gitignore` now un-ignores `plugins/chrome-profiles/scripts/fixtures/**/*.log`.

* **gmail-commander:** authored html part for draft builder ([374f64c](https://github.com/terrylica/cc-skills/commit/374f64c73769d5921035838265ab6f3faf6e6bb6))

A designed email (quotation cards, section rules, per-speaker accents) cannot be expressed by the minimal markdown-ish converter, and the CLI escapes any html it is given. --html &lt;file> makes the file the text/html part verbatim while --body still supplies text/plain.

Refused before upload (findAuthoredHtmlProblems): &lt;script>, inline event handlers, external resources (src/background/url()/&lt;link>), size past Gmail's ~102 KB clip, and any word of the --body text missing from the html or out of order, so the two parts cannot say different things. The word alignment bounds its lookahead and treats a match that skips the next expected word as a dropped word, so one missing common word is reported alone instead of cascading into every word after it.

After upload the stored html part must equal the file (CRLF-normalised); the forced-line-break check stays for converter output only.

* **orca-tools:** session-closeout waits for running work before closing ([b15d48b](https://github.com/terrylica/cc-skills/commit/b15d48bd5d1475b5275a32e635de419349ab1fd6))

Every form now reports what the session started that is still running, from three sources: the agent's process tree, a transcript ledger (background commands and agents without a task notification or TaskStop, session crons, a pending ScheduleWakeup) and Orca's per-tab status record (subagents and teammates, shells and monitors, task wake-ups), checked against this session's id and process.

--close no longer refuses on running work: it defers the close until that work has finished and Orca's row for the tab has settled (--settle-timeout, default 30 min). Meanwhile the tab title gets a [running] prefix and, when this is the workspace's only agent session, the workspace status becomes in-progress; an existing comment is prefixed, a missing one is never added, because Orca's CLI ignores an empty --comment. Naming alone starts a watcher that removes the markers.

Fixes: the closer trusted tui-idle, which ends while subagents still run; it skipped its re-check when the agent pid was gone; it was started by a relative $0 after changing directory to /, so a close requested as ./orca-closeout silently never happened; and a task notification arriving while it waited was taken for a typed prompt.

The skill keeps "Retire the session's own subagents and teammates" (ListAgents + TaskStop) as step 2 of five: the script sees that work, but only the agent can stop it.
