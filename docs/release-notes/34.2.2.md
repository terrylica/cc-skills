## [34.2.2](https://github.com/terrylica/cc-skills/compare/v34.2.1...v34.2.2) (2026-10-22)

This release makes `orca-spinoff` work against a paired Orca runtime, another computer reached with `--environment`. On such a runtime Orca refuses its built-in agent launcher with `agent_launch_replay_unsupported`: `worktree create --agent` and `agent launch` both failed, with the 1.4.235 and 1.4.237 CLIs against a 1.4.237 runtime, so a spin-off onto another machine stopped before any agent started. The script now creates the worktree there without an agent and types the agent and its prompt into the single shell tab Orca opens, so the one-tab rule still holds. The skill also documents two traps found doing it: Claude Code's folder trust belongs to the repository root, not a parent folder, and a remote that uses an SSH-alias host does not match one that uses `github.com`.

### Summary

- **orca-tools:** on a paired runtime, `orca-spinoff create` creates the worktree without `--agent`, then sends `<agent> '<prompt>'` to the worktree's own shell tab and titles it after the agent, falling back to `terminal create --command` only when no tab appeared.
- **orca-tools:** the 90-second prompt read-back is skipped on that route, where the agent's full-screen UI replaces the typed prompt; the script says how to confirm instead. A remote spin-off now finishes in about 6 s.
- **orca-tools:** SKILL.md explains the route and its three differences from the built-in launcher: the remote Orca's `agentDefaultArgs` are not applied, `prompt_seen` is false, and Claude Code asks for folder trust unless that machine trusts the repository.
- **orca-tools:** new pitfall: Claude Code's folder trust is per repository root (measured 2026-10-22), and an unapproved API key prompt defaults to No, so it must never be answered blind.
- **orca-tools:** the targeting table notes that an SSH-alias remote on one machine and `github.com` on the other do not match; pass `--repo-id`.

### Bug Fixes

* **orca-tools:** start the agent in the worktree's shell tab on a paired runtime, where Orca refuses its launcher ([0b81bdc](https://github.com/terrylica/cc-skills/commit/0b81bdc217ab87f84356def3482d9b56f7dde70d))

On a runtime reached with --environment, worktree create --agent and agent launch both fail with agent_launch_replay_unsupported (Orca 1.4.235 and 1.4.237 CLIs against a 1.4.237 runtime). orca-spinoff now creates the worktree bare, types the agent and prompt into the single shell tab Orca opens there, titles it, and skips the 90-second title read-back that cannot succeed on that route. SKILL.md documents the route, the --repo-id case for an SSH-alias remote, and that Claude Code's folder trust is keyed to the repository root, not a parent folder. Measured end to end on a paired macOS runtime: one tab, the agent's reply in its transcript, 6 s instead of 90+.
