## v33.4.0 — 2026-10-03

v33.4.0 lets FloatingClock tell the rest of the Mac when you deliberately choose an audio device. It came from a dictation bug: Typeless kept recording from the MacBook microphone while the clock correctly showed a USB wireless mic as the input. The fix is a separate daemon that keeps the macOS default input sensible. One of its jobs is to put the input back after AirPods connect, because macOS moves the microphone to them along with the sound. That rule cannot tell macOS's automatic routing apart from you picking the AirPods microphone on purpose in the clock. So the clock now announces each explicit choice with a standard distributed notification, and a policy like that can stand down instead of undoing your choice. The clock's own docs also gain a measured correction: Typeless 2.8.1's "Auto-detect" can ignore the system input entirely.

### Added

- **Explicit-selection broadcast** (`AudioDeviceSelectionMenuController.m`): every explicit IN or OUT choice posts `com.terryli.floating-clock.explicit-audio-selection`, with `userInfo.scope` set to `input` or `output`.
  - Covers menu picks, the left-click cycle, and Bluetooth connect-then-route.
  - Posted from `noteExplicitDeviceSelectionForInput:`, the same choke point that cancels the clock's own hijack guard, so the two can never disagree about what counts as a deliberate choice.
  - Fire-and-forget with `deliverImmediately:YES`. Nothing has to listen, and the clock behaves exactly as before when nothing does.
- **Broadcast contract** in `docs/overlay-indicators.md` § "Explicit-selection broadcast": what it carries, when it fires, and how a listener reads the device from the HAL instead of the payload.

### Changed

- **Typeless caveat corrected** in `docs/overlay-indicators.md`. The old note said Typeless resolves the default input once per session. The measured cause is worse: with the lid open, a hidden `dynamicMicrophoneDegradationEnabled` setting (on by default, not in the UI), and separately any click on "Auto-detect" in Typeless's picker, writes the built-in mic into `preferredBuiltInMicId`, and the recorder forces capture onto it.
  - The clock's IN zone can be correct while Typeless records from another mic.
  - The per-dictation ground truth is `history_v2.mic_device_info` in Typeless's `typeless.db`.

### Verified

- `make check` in `plugins/floating-clock`: build plus all 128 tests pass.
- Live on 2026-10-03, with the rebuilt clock installed under its persistent signing identity so its permission grants carried over:
  - Picking AirPods as input from the clock's real IN menu, driven through Accessibility, delivered the notification. A listening daemon logged the choice and left the AirPods input alone.
  - An AirPods reconnect with no pick in the clock was restored to the wired mic within about 1 s, with the output left on the AirPods.
