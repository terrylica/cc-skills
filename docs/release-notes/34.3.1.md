## [34.3.1](https://github.com/terrylica/cc-skills/compare/v34.3.0...v34.3.1) (2026-10-23)

This release adds one pitfall to the orca-tools `worktree-spinoff` skill, found while cleaning up after a test on a paired Orca runtime. Removing a repository from Orca and deleting its folders does not close the repository's terminal tabs. The tabs stay in the sidebar under "Unknown", their shells keep a working directory that no longer exists, and Claude Code started in one of them stops with "The current working directory was deleted". The skill now says how to clean up: once the worktree is gone, `orca terminal close --worktree … --all` cannot find it, so each tab has to be closed by handle, and the safe order is tabs first, then the worktree, then the repository.

### Summary

- **orca-tools:** new pitfall in `worktree-spinoff`: a removed repository's terminal tabs stay open, listed by `orca terminal list` even when `orca repo list` and `orca worktree list` are empty (measured 2026-10-22 on a paired runtime).
- **orca-tools:** symptom recorded verbatim: Claude Code started in such a tab fails with "The current working directory was deleted".
- **orca-tools:** `orca terminal close --worktree <selector> --all` returns `selector_not_found` once the worktree is gone; `orca terminal close --terminal <handle> --tab` closes each tab instead.
- **orca-tools:** cleanup order documented: close the tabs, then remove the worktree (`orca-spinoff remove`), then the repository.
- No code changes; the `orca-spinoff` script and every other plugin are unchanged.
