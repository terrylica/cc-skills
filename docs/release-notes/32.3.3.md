## v32.3.3 — 2026-09-28

v32.3.3 makes the review-round gate measure the branch a pull request actually submits. The gate read the repository and HEAD from the session's working directory. When a PR is opened from a worktree, the session typically stands in the main checkout on `main`, and `gh pr create --head <branch>` names the real branch. So the gate measured `main` (zero changed files, no record) and denied a branch whose self-review was recorded at its exact commit. Changing into the worktree was no remedy either, because the harness's worktree isolation can refuse every git command there. On 2026-09-28 two relay-monitor PRs (#133, #139) could only be opened with the gate's override. Now, for `gh pr create`, the gate reads the `--head` branch, finds the local worktree that has it checked out, and measures that worktree instead.

### Fixed

- `pretooluse-review-round-gate`: for `gh pr create`, a `--head` / `-H` / `--head=` branch (an `owner:branch` form keeps the branch) is resolved to the local worktree that has it checked out, and repo identity and diff facts come from there ([538c04f](https://github.com/terrylica/cc-skills/commit/538c04f8)).
- With no `--head`, or no local worktree for it, the gate uses the session's directory exactly as before, so an unresolvable head never widens what is allowed.
- `gh` must be in command position: `echo gh pr create --head x` names no branch.

### Tests

- 14 parser cases: flag spellings, fork syntax, value-taking flags that must not be read as the head, operator boundaries, command position.
- 4 end-to-end cases against real git worktrees, each with a control:
  - a reviewed `--head` branch is allowed from the main checkout;
  - the same command without `--head` is still denied;
  - an edit after the record is still denied;
  - a `--head` with no worktree falls back and is denied.
- `moon run repo:check` passed before the push.

### Upgrade notes

- Nothing to do. A `gh pr create` from a worktree now needs only the usual `review-round-cli.ts record` run inside that worktree, and no `REVIEW_ROUND_OK` override.
