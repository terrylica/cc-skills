## [34.2.1](https://github.com/terrylica/cc-skills/compare/v34.2.0...v34.2.1) (2026-10-22)

This release closes out the follow-ups from v34.2.0. FloatingClock's mic-mute indicator, the last part of the app that queried CoreAudio on the main thread, now does all its HAL work on a private queue, so no audio query can freeze the clock any more (#52, closing #37). The quant-research skills drop MinBTL, the trial-count-based minimum backtest length, and the ranking case study no longer uses it or the Deflated Sharpe Ratio (#53, closing #51). The compute_metrics CLI now writes strict JSON instead of crashing on a numpy bool or emitting NaN (#54, closing #44). No configuration or command changed for users.

### Summary

- **floating-clock:** the mic-mute indicator's binding, mute listener, metering start/stop and banner click run on a private `mic-hal` queue; a live sample shows no CoreAudio call on the main thread ([#52](https://github.com/terrylica/cc-skills/pull/52), closes [#37](https://github.com/terrylica/cc-skills/issues/37)).
- **quant-research:** MinBTL is removed and named beside DSR in every banned-methods note ([#53](https://github.com/terrylica/cc-skills/pull/53), closes [#51](https://github.com/terrylica/cc-skills/issues/51)).
- **quant-research:** the evolutionary-metric-ranking case study is rewritten without DSR or MinBTL; the original run's cutoffs are kept as history and flagged where they depended on the removed metrics ([#53](https://github.com/terrylica/cc-skills/pull/53)).
- **quant-research:** `compute_metrics.py` writes strict JSON: numpy values become plain types, NaN/inf become null, and output uses `allow_nan=False`; a CLI-path test now runs in the gate ([#54](https://github.com/terrylica/cc-skills/pull/54), closes [#44](https://github.com/terrylica/cc-skills/issues/44)).
- **quant-research:** the metrics schema allows null `skewness` and `kurtosis` ([#54](https://github.com/terrylica/cc-skills/pull/54)).


### Bug Fixes

* **floating-clock:** mic-mute indicator reads CoreAudio off main ([b157c28](https://github.com/terrylica/cc-skills/commit/b157c280fa299443457e49a8b8e77dd8f28f0a8e)), closes [#37](https://github.com/terrylica/cc-skills/issues/37)

FCMicMuteIndicator was the last place FloatingClock queried the HAL on the main thread: every 1 Hz tick read the default input and the input mute flag there, rebinding started and stopped the silence-meter IOProc there, and its three property listeners were delivered on the main queue and read the HAL in their handlers. A stalled coreaudiod or IO context would freeze the clock through any of them.

All of that now runs on one private serial queue (com.cc-skills.floating-clock.mic-hal): the device binding, the mute listener, metering start and stop, the banner's clear-the-flag click, and the listeners themselves, which Apple dispatches asynchronously onto the queue they were registered with. The main thread keeps only the banner: -refresh enqueues a coalesced HAL pass, the pass hands the mute flag back to main, and -renderMuteFlag: composes the banner from it and the meter's silence flags. _micAuthorized and _meteringStarted became atomics because they now cross the two threads.

Verified on the installed build: a 6 s sample shows no HAL call on the main thread (two per sample before), and setting the input mute flag with SwitchAudioSource raises the red MIC MUTED banner, which clears when the flag is cleared.

* **quant-research:** compute_metrics CLI writes JSON for numpy values ([4bdfc19](https://github.com/terrylica/cc-skills/commit/4bdfc1910499bb6251a02cc6df6294dd50b406da)), closes [#44](https://github.com/terrylica/cc-skills/issues/44)

Running scripts/compute_metrics.py from the command line raised "TypeError: Object of type bool is not JSON serializable when serializing dict item 'is_collapsed'", while calling evaluate_fold directly worked. detect_model_collapse computed is_collapsed as a numpy comparison, so the value was np.bool_, which the json module refuses. Library callers never serialise the dict, so only the CLI's json.dumps hit it.

The same boundary had a quieter latent defect: non-finite floats. sortino_ratio is inf when no day loses, and skewness or kurtosis are NaN for constant daily PnL; json.dumps emits these as the bare tokens Infinity and NaN, which are not JSON and which strict parsers (JSON.parse, jq) reject. references/metrics-schema.md types such metrics as number or null.

The fix casts is_collapsed to bool where it is computed, and adds to_json_native at the serialisation boundary: numpy scalars become bool, int or float, arrays become lists, and NaN or infinity become null. The CLI now serialises through dumps_metrics with allow_nan=False, so any value that slips past the conversion fails loudly instead of producing invalid JSON. main() accepts an optional argv.

compute_metrics.test.ts runs the real CLI through uv in a subprocess (single fold to stdout, a collapsed fold with infinite and NaN metrics via --output, and --aggregate over the folds' own output) and parses every result with JSON.parse. It fails on the previous code with the TypeError above. It is a Bun test because repo:test runs every tracked *.test.ts and no gate task runs Python test files. A python-allowlist.toml for the plugin records why this script stays Python.
