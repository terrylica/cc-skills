## [34.19.0](https://github.com/terrylica/cc-skills/compare/v34.18.2...v34.19.0) (2026-11-16)

This release adds a way to measure the hook system as a whole before changing it. A session here loads 130 hook registrations and the four itp-hooks orchestrators run 57 sub-hooks inside them, yet nothing recorded what that system blocks, lets through or costs: Claude Code writes a transcript record only for a hook that prints something, and the orchestrators measured each sub-hook's time and discarded it. `hook-census` reads what already exists (settings, plugin manifests, session transcripts) and adds the one missing measurement, per-sub-hook timing, inside a window the operator opens and that closes itself. Everything it writes is payload-free: tags, ids, counts and milliseconds, never a command or prompt.

### Summary

- **New: `plugins/itp-hooks/scripts/hook-census.ts`.**
  - `inventory`: every handler per event from settings files, enabled plugins and module plugins, with the orchestrators' sub-hooks parsed statically from their registries, and a diff between two launchers.
  - `outcomes`: denies, asks, contexts, decision blocks, timeouts and errors per guard tag, streamed from `.jsonl` and Brotli `.jsonl.br` transcripts one file at a time.
  - `timing`: p50, p95 and max per hook, sub-hook and event, and overhead per session.
  - `rules`: validates a standing-rules TOML against the instruction files and the hooks that really load.
  - `report` and `window`: writes everything with `REPORT.md` and a `labels.toml` for marking false blocks; opens or closes the timing window.
- **Changed: the four orchestrators** record each sub-hook's elapsed time and verdict through `hooks/lib/orchestrator-subhook-timing.ts`, only while a timing window is open, from a fixed key list, and fail open. The Bash orchestrator gains per-guard timing for the first time. No verdict or timeout changes.
- **Tests:** 17 census tests (every transcript record shape, a Brotli transcript, a two-launcher config root, the real registries, the rules validator, an interpreter-list drift check) and 10 timing tests; the test preload keeps test runs out of a live window.
- **Measured on real data:** deny counts for three guards match an independent `rg` count exactly inside the window; a 3-day scan read 206 files in 4.8 s at 195 MB peak memory.
- **Docs:** new spoke `plugins/itp-hooks/docs/hook-census.md`; entries in the plugin hub and spoke index.
