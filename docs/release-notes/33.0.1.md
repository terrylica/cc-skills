## v33.0.1 — 2026-10-01

v33.0.1 is a performance release for the hook layer that runs on every Bash command. Until now, each Bash tool call started 26 itp-hooks bun processes, one per guard, and all of them were unconditional. Twenty-four of those guards now run inside a single process, `pretooluse-bash-guard-orchestrator.ts`. Measured on one Bash call, guard CPU falls from 295 ms to 28 ms and the process count from 24 to 1. No guard's logic changed: each still has its own file, its own standalone entry point and its own tests. A differential test runs every guard standalone and requires the orchestrator to reach the identical decision. The cheaper option, the hooks `if` field, was measured first and rejected: it skipped 9 of 15 wrapped command forms, such as `bash -c`, absolute paths, `env`, heredocs and `ssh`, which every guard currently catches.

### Changed

- **Bash guard orchestrator** (#111, #177): one process runs the 24 guards with Claude Code's own precedence for parallel hooks (deny > ask > allow).
  - The first deny wins.
  - An ask is held while later guards are checked for a deny.
  - Context nudges are joined.
  - Each guard is crash-isolated, time-boxed and fails open, as it did standalone.
- `hooks.json` goes from 26 Bash entries to 3. The two command-rewriting guards (`subprocess-stdin-inlet`, `pueue-wrap`) stay separate because Claude Code keeps only the last hook's `updatedInput`, and pueue-wrap stays last. `process-storm-guard` and `broad-process-signal-guard` keep a `Write|Edit|MultiEdit` entry for file content.
- Each guard exports its existing `main()` and only calls it when run directly. `pretooluse-helpers.ts` gains `runGuardMainInProcess()`, which gives each run its own `AsyncLocalStorage` context, so a guard that overruns cannot write into another guard's result.
- Each guard's `hooks.json` description now lives in `BASH_GUARD_REGISTRY`. A new invariant in the itp-hooks hub says a new Bash guard goes into that registry, not `hooks.json`, and a new spoke, `docs/pretooluse-bash-guard-orchestrator.md`, documents the mechanism.

### Added

- `pretooluse-bash-guard-orchestrator.test.ts`: a differential test over 14 commands (deny, ask precedence, a context nudge, wrapped forms, pass-throughs) against standalone runs, plus aggregation tests for short-circuit, fail-open, and late output after a timeout.
