## [34.18.2](https://github.com/terrylica/cc-skills/compare/v34.18.1...v34.18.2) (2026-11-16)

This patch gives the publishing-standard reminder the same fix 34.18.1 gave the Cloudflare sitemap reminder. It recognised publish commands by text patterns, so a command that only mentioned one (reading a deploy script, a note or commit message naming `wrangler deploy` or `vercel --prod`) used up the session's one reminder before the real publish. The reminder now reads the command with the shared shell-command walker and fires only before an invocation the shell would actually run.

### Summary

- **itp-hooks, `publishing-standard-reminder`** (`isPublishCommand`).
  - **Counted:** `wrangler deploy`, `wrangler pages deploy` and `wrangler versions deploy`, `orca artifacts share` or `update`, `netlify deploy`, `vercel deploy` or `vercel --prod`, `firebase deploy`, `surge <dir>` and `gh-pages -d`. Each counts when run directly, through `npx`, `bunx`, `pnpx` or `pnpm`/`yarn dlx` (a trailing `@version` dropped), behind `env`, `timeout` or `sudo`, or inside `bash -c` or `ssh`.
  - **Ignored now:** quoted text, comments, heredoc bodies fed to anything but a shell, and arguments of other programs.
  - **Unchanged:** dry runs and help are not publishes; `PUBLISHING-STANDARD-OK` still skips; once per session at each of its two moments.
- **Docs:** the spoke's table names the mention case.
- **Tests:** five mention cases added; 34 pass.
