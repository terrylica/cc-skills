## v32.6.0 — 2026-09-30

v32.6.0 is a housekeeping release that makes the local quality gate actually guard the repository. Before it, `moon run repo:check` was described as "the gate that must pass before a push", but nothing ran it at push time. Its timing caps were stricter than the release gate's own, its unit suite could not say which file had failed, its link check was defined but never run, and five audit scripts ran nowhere. Now a pre-push hook runs the whole gate after the account check. The gate also covers the spawnSync invariant and the offline link check, the latter green for the first time after every one of the 235 broken internal links was fixed. A failing unit test now names its file and line. Along the way the release removes a dead hook, orphaned docs and dated CLAUDE.md history. It also fixes an incident found while building the gate: a git hook that runs a test suite has to clear git's repository environment first, or the tests write into the repository being pushed.

### Added

- **Pre-push gate** (#166): `bash scripts/install-hooks.sh` installs a dispatcher that runs the global account-check hook, then `tasks/hooks/pre-push-gate`, which runs `moon run repo:check`. Deletions and tag-only pushes skip it, as does `PREPUSH_GATE_OK="<reason>"`; release pushes declare themselves that way.
- **Failure roster for the bun unit suite** (#143): every failing test is printed as `BUN-UNIT-FAIL <file>:<line> — <test>`, read from bun's JUnit report, so a tail of the log locates it. Nothing is piped, so bun's exit code stays the verdict.
- **New gates in `repo:check`**: `repo:audit-orchestrator-spawnsync` (#168) can no longer pass vacuously, and `repo:link-check` (#169) runs offline. The cache-drift audit is registered as `repo:diagnose-cache-drift`.
- README section for Windows users hitting `EPERM` on `marketplace add` (#162).

### Changed

- The Stop-hook `ty` check no longer forces `--python-version 3.14`. ty resolves the repo's own pin itself, falling back to its 3.14 default (#157, from @zerone0x's #158).
- `repo:test-hooks` skips absolute wall-clock caps under load, the same way release preflight does (#142).
- Root and plugin CLAUDE.md files drop dated history, superseded rules and a hand-maintained gate list that had drifted (#165, #169).

### Fixed

- **The pre-push gate cleared none of git's hook environment** (#167). The first gated push ran the suites with `GIT_DIR` inherited, and fixture tests wrote commits, a staged mass deletion and config changes into this repository. Nothing reached the remote and the state was repaired. The gate and both suite runners now unset exactly what `git rev-parse --local-env-vars` lists, as githooks(5) prescribes.
- All 235 broken internal links (#169): home-directory links became inline code, badge links with empty targets became plain images, and the rest were retargeted, re-anchored or unlinked.
- An intermittent exit 141 (SIGPIPE under `pipefail`) in the iter-92 audit, which was retired. The live GitHub-render tests now get a 30 s network timeout. The plugin-count drift (42 → 43) that kept `repo:check` red is fixed.

### Removed

- The unregistered mini-inngest doctrine hook and its registry entry, three one-off audits with their tests, orphaned research docs, a one-time migration script for a removed plugin, 22 skill-creator eval outputs shipped inside a plugin, and the obsolete `.claude-plugin/plugins` symlink (#164, #165, #168).
