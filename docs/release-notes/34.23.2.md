## Narrative

This patch release corrects two instructions in the bootstrap-monorepo skill that produced a repository which looked fine and was not. The skill told new repositories to tag their moon projects as `lang:rust` and `layer:engine`. moon 2.x accepts only letters, digits, `-`, `/`, `_` and `.` in a tag, so a project scaffolded from the skill stopped at its first `moon` run (moon 2.6.5: `Invalid identifier format`). Separately, the skill's Biome example used `"recommended": true`, which Biome 2.6 deprecates; running `biome migrate` on it writes `"preset": "none"`, which turns every lint rule off without any warning, so the lint task kept passing while checking nothing. Both were measured while scaffolding a new extension repository on 2026-11-22, and both examples now show the form that works.

## Documentation

- **moon tags:** every example tag in the bootstrap-monorepo reference now uses `/` (`lang/rust`, `layer/engine`, `lang/ts`, `layer/control-plane`, `lang/python`, `layer/library`) instead of `:`, which moon 2.x rejects in a tag.
- **The rule stated once:** the "Tags on every project" step names moon 2.x's allowed tag characters, so a new tag scheme can be checked against it before the first `moon` run.
- **Biome preset:** the example `biome.json` sets `"rules": { "preset": "recommended" }` instead of the deprecated `"recommended": true`.
- **Biome migrate warning:** a note records that `biome migrate` rewrites the deprecated form as `"preset": "none"`, which switches every rule off silently (measured with Biome 2.6.8), so the preset must be set by hand after migrating.
- **Nx convergence unchanged:** `/` tags still map one-to-one onto Nx project tags for dependency-boundary rules, so the reason the skill asks for tags at all still holds.
