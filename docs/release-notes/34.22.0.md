## Narrative

This release adds the Braille Tally, a way to rank anything a person reads on several axes at once without merging them into one score. A tally is a short run of Braille cells, one per axis, where level n of 8 is the cell with exactly n dots (⡀⣀⣠⣤⣴⣶⣾⣿); the default axes are Importance · Urgency · Simplicity, in that order, and items are ordered by Pareto front. Braille cells were chosen because they hold their shape in plain text: measured in a replica of Gmail's subject line, the Unicode block characters ▁…█ come from three different fonts and misalign, while one font draws every Braille pattern with one width and one bottom line. The new `braille-tally` plugin makes the tally a habit rather than a memory: a guard on AskUserQuestion asks for a tally on every option, a legend in the question and the options in rank order.

## Added

- **`braille-tally` plugin and skill:** the convention (axes, legend, relative levels, Pareto ranking, where tallies go in lists, questions, plain text and HTML) and the measurements behind it (#117).
- **`scripts/braille-tally.ts` CLI:** `tally`, `parse`, `legend`, `html` (drawn from the Braille bit pattern, so it needs no font in email or web pages), `rank` (JSON lines in, ranked list with fronts out) and `spec` (machine-readable command set) (#117).
- **`lib/tally.ts`:** the dependency-free implementation other code can import (#117).
- **AskUserQuestion guard:** a PreToolUse hook that denies a question until every option label starts with a tally, the question text carries the legend, and the options are in rank order. It names the exact fix and fails open on anything unexpected (#117).
- **ADR and design spec:** `docs/adr/2026-11-20-braille-tally.md` and `docs/design/2026-11-20-braille-tally/spec.md` (#117).
