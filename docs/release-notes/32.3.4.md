## v32.3.4 — 2026-09-28

v32.3.4 lets git run again in worktree-isolated Claude Code sessions. The `itp-hooks` stdin-inlet guard rewrote every Bash command to `(CMD) < /dev/null`, so that no subprocess could block waiting on the caller's stdin. Claude Code's worktree isolation checks the command it will actually run, after the hook's rewrite, and it cannot verify git inside a subshell with a redirect. So in every worktree session every git command was refused, including a bare `git status` (#161, measured on Claude Code 2.1.283 in a ccmax-monitor worktree). The guard now emits `exec < /dev/null` on its own line ahead of the command. POSIX makes a redirect-only `exec` apply to the current shell, so every later command still reads `/dev/null`, and each Bash tool call starts a fresh shell, so it does not carry into the next call.

### Fixed

- `pretooluse-subprocess-stdin-inlet-guard`: prefixes `exec < /dev/null` instead of wrapping the command in a subshell ([#160](https://github.com/terrylica/cc-skills/pull/160), closes #161).
- A command ending in a `#` comment no longer swallows the wrap's closing parenthesis. The old rewrite broke it.

### Changed

- `.prototools`: moon 2.5.5 → 2.5.6 (the proto pin auto-bump).

### Tests

- The iter-63 suite is 9 assertions over 6 inputs. #01 was inverted, not deleted; #03 checks that an already-redirected command passes through unchanged; #08 covers a trailing `# comment`; #09 checks that a compound `cat; echo done | cat` reads `/dev/null`.
- Mutation-checked: with the old hook, exactly #01 and #08 fail. `moon run repo:check` passed before the merge.

### Upgrade notes

- Update the `itp-hooks` plugin. Worktree sessions then run git with no override, and nothing else changes.
