## [34.11.0](https://github.com/terrylica/cc-skills/compare/v34.10.0...v34.11.0) (2026-10-30)

A reply that quotes the person being answered now arrives the way it should: each of their passages as a styled quotation, any file attached, built by one command that proves what Gmail stored. The canonical draft builder rendered quotes well but could not attach a file, so a reply that had to carry a signed document either lost its styled quotes through the CLI or needed Gmail's web compose, which rewrites the plain part when it saves. The builder now takes `--attach` and verifies every stored attachment by SHA-256, and the gmail-access skill makes this the documented house style for every reply, so every machine with the plugin and every new session drafts replies the same way.

### Summary

- **gmail-commander:** `gmail-draft.ts --attach <file>`, repeatable. The message becomes multipart/mixed around the usual alternative body; without the flag it is byte-for-byte what it was.
- **gmail-commander:** missing, empty or oversized (over 25 MB) attachments are refused before any token or network call. Filenames are escaped, and non-ASCII names go out as encoded-words.
- **gmail-commander:** the post-write read-back searches nested parts, downloads every stored attachment and compares its SHA-256 with the file sent. The JSON output lists each attachment's byte count and hash.
- **gmail-commander:** the gmail-access skill gains "Replying to someone: the house style": the exact command, the multi-line sign-off recipe, the two draft paths compared, and triggers that load it for any reply. It also records that a bare `--from` stores no display name, and that the attribution parser misses quoted history under an unprefixed `On … wrote:` line.
- **gmail-commander:** nine new tests, shown to fail when the empty-file check or the mixed wrapper is broken on purpose; 195 tests pass across the plugin's scripts and hooks.
