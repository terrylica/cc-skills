## Narrative

This patch release makes the PII push gate measure what a push actually publishes. The gate used to compare the branch's tree with its upstream's, which reported changes the push does not make and missed some it does. On a branch that tracked `origin/main`, files that main deleted after the branch point were reported as added. After main was merged into a pull request branch, everything main had added since was reported, though GitHub already published it, so resolving two pull requests needed escape markers for lines that were already public. A value added in one commit and removed in a later one netted out and passed, though the first commit still carried it to the remote. The gate now reads the commits the remote does not have, each as its own diff, and counts a merge only for the lines written while resolving it. The release also corrects three install instructions that the vendored packages in 34.21.0 had left describing the old layout.

## Fixed

- **PII push gate range:** the gate scans the commits the push remote lacks (`HEAD --not --remotes=<remote>`), each as its own diff, instead of a tree diff against `@{u}`, so files main deleted after the branch point are no longer reported as added. The remote is the branch's upstream remote, else `origin` (#125, #128).
- **Merges into a pull request branch:** a merge commit contributes only the lines that are new against every parent (dense combined diff), so merging an already-published main no longer reports main's content (#125, #128).
- **Added then removed:** a value added in one commit and deleted in a later one inside the same push is now reported, because the earlier commit still publishes it (#125, #128).
- **Tests on real repositories:** four cases build a repository with a bare remote; the three range cases fail when the old `@{u}..HEAD` diff is restored (#128).
- **tlg setup and CLAUDE.md:** no longer tell agents to run `bun install`, because GramJS is vendored in `scripts/vendor/` (#126, #127).
- **pushover-commander headless dashboard skill:** `playwright-core` comes from the plugin root's `package.json`, not `skills/_lib/`, which has no `package.json` (#126, #127).
