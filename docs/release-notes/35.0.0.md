## Narrative

This release lets the tlg plugin show what a Telegram message answers. Until now `read` printed only `[time] (id:N) Name: text`: which earlier message a reply answered, the part of it the sender quoted, a forward's origin, a media item beside its caption, an album or a forum topic were all invisible. Tracing one quoted reply in a private chat on 2026-11-26 took a full `dump` of the chat and a hand walk along `reply_to_msg_id`. Now `read`, `search` and a new `thread` command share one formatter that reads those fields from Telegram's own message header (`replyTo.replyToMsgId`, `quote`/`quoteText`, `forumTopic`/`replyToTopId`, `replyToPeerId`, `fwdFrom`), and `thread` walks the reply chain in one call. The version is major for two changes of output: listings print local time with its zone label, and `dump` writes album ids as strings. A reply watcher that polls `read` on one of our machines was checked against the new lines with its own filter, and the line header it matches keeps its old shape.

## Added

- **`thread <chat> <id> [--depth N] [--replies] [--scan N] [--json]`:** the reply chain oldest first, ending at the message (▶). It says where it stopped: the start of the conversation, a forum topic's root, a deleted parent, a parent in another chat, a cycle or the depth limit. `--replies` also lists later replies found in the next `--scan` messages.
- **`read --around ID | --after ID | --before ID`, `--topic ID` and `--json`:** context around one message without a dump. Private-chat ids are numbered across the whole account, so neighbouring ids are not neighbouring messages.
- **Listing markers after the sender:** `↩N` (the message it replies to), the quoted part on its own line as `❝…❞`, `topic:T`, `album:G`, `(edited)`, `[fwd from X]`, the media kind beside a caption and `[service: …]`. Global search names each result's `{chat}` and its sender.
- **`dump` fields:** `reply_parent`, `quote_text`, `reply_to_peer`, `forum_topic_id`, `fwd_from`, `out` and `action`. `--after ID` writes `messages-after-ID.ndjson` beside the full archive, never over it.
- **The link check covers e-mail addresses:** on 2026-11-23 a greedy e-mail entity swallowed the Chinese word before an address; `relink` trims such an entity to the address alone.
- **send-message skill, "Replying to a specific message":** run `thread` before answering a quote, reply with `--reply-to` to the exact message, and delete a superseded unanswered message before sending its replacement.

## Changed

- **Breaking: listing times are local, with the zone's label** (e.g. PCT); `--utc` prints UTC as before. Global search lines gain the sender and a `{chat}` marker.
- **Breaking: `dump` writes `grouped_id` as a string.** Album ids exceed 2^53, so the JSON number lost its last digits and could not be matched to the album's messages.
- **`(id:N)` and the sender label keep their old form,** and every new marker follows the sender, so a script matching `^\[[^]]+\] \(id:[0-9]+\)` followed by a sender label still works. A contract test holds the shape.

## Fixed

- **Counts are bounded:** GramJS reads a limit of 0 or NaN as "no limit", so `-n`, `--depth` and `--scan` must be whole numbers of at least 1, and `--reply-to` a whole number. Both are refused before connecting.
- **`send-file` checks the caption's length, footer included, before uploading:** 1,024 characters, or 4,096 on a Premium account. Telegram used to refuse it only after the upload.
- **A footer without a session id is no longer stamped twice.**
- **`tsconfig.json`** now type-checks `session-footer`, `profile-hint` and `message-format`, which had escaped it.
