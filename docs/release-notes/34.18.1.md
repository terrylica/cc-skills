## [34.18.1](https://github.com/terrylica/cc-skills/compare/v34.18.0...v34.18.1) (2026-11-15)

This patch stops the Cloudflare sitemap reminder from treating a mention of a deploy as a deploy. It used to match the deploy text anywhere in a command, so reading a deploy script with `cat`, `sed` or `grep`, quoting a deploy in a commit message, or writing a note that names one recorded a "deploy". The Stop check then refused to end the turn until the sitemap was rebuilt; one session was blocked about six times in a day without deploying anything. The detector now reads the command with the shared shell-command walker the other Bash guards use, and counts only an invocation the shell would actually run.

### Summary

- **itp-hooks, `isDeployCommand`** (`lib/cloudflare-deploy-sitemap.ts`).
  - **Counted:** `wrangler deploy`, `wrangler pages deploy` and `wrangler versions deploy`. They count when run directly, through `npx`, `bunx`, `pnpx` or `pnpm`/`yarn dlx`, behind `env`, `timeout` or `sudo`, or inside `bash -c` or `ssh`. A `workers_deploy.sh` wrapper counts when run directly or through a shell.
  - **Ignored:** quoted text, comments, heredoc bodies fed to anything but a shell, and arguments of other programs (`cat`, `sed`, `grep`, `echo`, `git commit -m`).
  - **Unchanged:** `--dry-run`, `-h` and `--help` are not deploys; the sitemap tool itself never counts; the escape marker still skips.
- **Tests:** seven mention cases taken from real sessions and six run forms; 29 pass.
