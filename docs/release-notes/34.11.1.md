## [34.11.1](https://github.com/terrylica/cc-skills/compare/v34.11.0...v34.11.1) (2026-10-30)

The status line's gateway segment could keep showing an alarm long after it had stopped being true. When every refresh of the gateway's `/v1/router-status` failed, for example on a network that resets TLS for the gateway's hostname, the segment rendered the last cached snapshot as the present state, with no limit on its age: on 2026-10-30 it showed `✗9/17 5m outage` for a snapshot more than an hour and a half old, while the gateway itself reported that it was serving. This release bounds how old cached evidence may be and says so when it is too old, adds an optional second URL to the same gateway, lets the real-traffic damper change the label you see and not only the log, and stops a failing network from slowing every render. The plugin's own test suite also stops writing into the developer's real telemetry and calling the real GitHub API.

### Summary

- **statusline-tools:** a cached snapshot older than `STATUSLINE_GATEWAY_STALE_AFTER_SECS` (default 300 s, the gateway's own observation window) is no longer shown; the segment renders `⌁<curl exit code> <age> stale`, for example `⌁35 1h stale`, so the failure and its cause are both visible.
- **statusline-tools:** `STATUSLINE_GATEWAY_FALLBACK_BASE_URL`, optional and empty by default, names a second URL to the same gateway, tried only when the primary refresh fails. Empty means no second request is ever made.
- **statusline-tools:** the real-traffic damper (this session's own requests completing through the gateway) now downgrades the rendered label from a red `outage` to a yellow `flapping`. Before, it changed only the logged class, and the log recorded 751 renders that said `transient` while the screen said `outage`.
- **statusline-tools:** after a refresh in which every URL failed, renders stop probing for `STATUSLINE_GATEWAY_REFRESH_BACKOFF_SECS` (default 30 s). Measured against a URL that accepts connections and never answers: 4.32 s per render before, 0.20 s per render inside the back-off.
- **statusline-tools:** `gateway-state.jsonl` schema v4 records the age of the data each render used, both URLs' curl exit codes and which URL answered.
- **statusline-tools:** the reader for the gateway's retired synthetic-canary health block is removed, with its `since-boot` label; the gateway no longer emits that block, and none of the roughly 39,000 renders logged since 2026-10-19 carried a value only it could produce.
- **statusline-tools:** every test now runs in its own `HOME`. A single plain test render used to append to the developer's real `gateway-state.jsonl` and `statusline.jsonl` and probe the developer's real gateway; the proxy test used to call the GitHub API with real credentials and now uses a fake `gh` that answers only when no proxy variable reaches it.
- **statusline-tools:** a severity glyph with no evidence to show is followed by one space, not two (`gateway 2/3 ⚠ flapping`).
