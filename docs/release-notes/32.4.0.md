## v32.4.0 — 2026-09-30

v32.4.0 gives the marketplace one shared way to let Claude Code drive a browser on macOS. The new `chrome-profiles` plugin lets you pick a profile of your everyday Google Chrome by its account email, rather than by a folder name like `Profile 7`, which differs on every machine and silently drifts. With Microsoft's Playwright Extension and a token kept in the macOS Keychain, Claude Code can then control that one signed-in profile without a single click. One command, `chrome-profile.sh setup <email>`, takes a fresh Mac all the way there, and `doctor` checks Chrome's version, the remote-debugging toggle and every registered browser server. The plugins that already drove Chrome now reuse it: web-forge, gh-tools' token engine and gemini-deep-research launch and stop Chrome through its one port script rather than each running its own copy, and the itp-hooks guard points there. Nothing personal ships with the plugin: account emails are typed in when you run it, and tokens never leave your Keychain.

### Added

- `chrome-profiles` plugin: the `browser-automation` skill (when to use a real browser at all, which route, and the safety rules), a reference on the underlying mechanics, `scripts/chrome-profile.sh` (`setup`, `setup-main`, `doctor`, `resolve`, `open`, `extension-status`, `playwright-mcp`) and `scripts/chrome-debug-port-control.sh` (`up` / `status` / `down` for a separate profile on a debug port).
- `gh-tools` issue-create now ships its GitHub image uploader, `scripts/gh-issue-image-upload.ts`. The skill had documented it while the script lived only outside this repo.

### Changed

- `web-forge`'s `browser-forge.mjs` and `gh-tools`' `gh-fine-grained-pat/scripts/browser.mjs` launch and shut down Chrome through `chrome-debug-port-control.sh`. Verified live: Chrome is up in about one second, Playwright attaches, and shutdown leaves nothing listening. `--remote-allow-origins=*` was dropped, since attaching works without it.
- `gemini-deep-research`'s skill, client, doctor and DOM probe now share one launch command and one profile path; before this they named three different paths.
- `web-forge`, `gh-tools` and `gemini-deep-research` declare `requires: chrome-profiles`. `dashboard-forge`, `gh-fine-grained-pat`, `issue-create`, the Pushover dashboard skill and the itp-hooks chrome-debug-port guard (its doc and its block message) point at the plugin instead of restating Chrome-136 rules.
- `playwright-core` ^1.58.2 → ^1.63.0. 1.58 expected Chromium build 1208, which is no longer installed alongside current Playwright; 1.63 matches build 1243.

### Removed

- The stale npm `package-lock.json`. It did not contain `playwright-core`, had not changed since 2025-12, and nothing ran `npm ci`; `bun.lock` is authoritative.
