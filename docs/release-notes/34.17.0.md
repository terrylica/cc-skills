## [34.17.0](https://github.com/terrylica/cc-skills/compare/v34.16.0...v34.17.0) (2026-11-15)

This minor release adds battery status and Bluetooth control to FloatingClock, and makes the statusline say when a session's id cannot be resumed yet. FloatingClock gains a power rail directly below the network rail: the Mac's battery on the left, Bluetooth on the right. Bluetooth shows its power, a shortcut tip and every device with its own battery, AirPods left, right and case included. Every battery field beyond the percentage and its state can be shown or hidden from the rail's right-click menu, and whatever the bar hides stays in the tooltip. Bluetooth can be switched from the rail, from its menu, or by `floating-clock --bluetooth on|off|toggle`, which a global hotkey can run. The running app performs the switch, so the Bluetooth permission stays with the app. The rail reads no system state on every tick: it follows the system's own change notifications, because a one-second Bluetooth reader was measured sending `bluetoothd` about 20 messages a second (exelban/stats#3623). The rail is off by default, because listing devices asks for the Bluetooth permission. The statusline fix closes a trap after an IDE restores a terminal tab with `--fork-session`: the fork's new id was shown as the session id although nothing had been saved under it, so resuming it failed.

### Summary

- **floating-clock, power rail** ([#93](https://github.com/terrylica/cc-skills/pull/93), closes [#92](https://github.com/terrylica/cc-skills/issues/92)).
  - **Battery:** the percentage and state are always shown (`⚡` charging, `⏸` held below full on AC, `✓` full, `▾` on battery). Six optional fields: time to full or empty, power in or out, adapter watts, health, cycles, temperature. Health falls back to `BatteryData.NominalChargeCapacity` where newer macOS moved it (exelban/stats#3392).
  - **Device batteries:** read from the accessory power sources `pmset -g accps` lists (measured: no entitlement needed, and an AirPods case reported over Bluetooth LE), the HID battery service and IOBluetooth's own battery properties.
  - **Control:** click the power dot to toggle Bluetooth, or a device name to connect or disconnect it; the right-click menu lists every paired device.
  - **Shortcut tip:** the chord of the hotkey that runs the toggle, read from a JSON registry a hotkey daemon publishes (`PowerRailHotkeyRegistry`), so the tip follows a re-bind.
  - **Off by default:** `PowerRailEnabled`, because listing devices asks for the Bluetooth permission.
- **statusline-tools, session line** ([#89](https://github.com/terrylica/cc-skills/pull/89), closes [#87](https://github.com/terrylica/cc-skills/issues/87)): while the transcript file is missing, the line adds `(not saved until the first message)`. For a `--fork-session` session it also names the parent id, which is the one that resumes.
- **Tests:** six new FloatingClock cases (156 in all) and three statusline cases (57 in all), each new statusline case failing on a broken copy of the code.
