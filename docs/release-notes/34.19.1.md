## [34.19.1](https://github.com/terrylica/cc-skills/compare/v34.19.0...v34.19.1) (2026-11-16)

This release fixes a privacy defect in `hook-census`, which promises outputs that hold only tags, ids, counts and milliseconds. The first 30-day report showed hook ids such as a single prompt word, an e-mail address and a host name. Claude Code's `command` field is not always a command: for a prompt hook it holds the prompt with the user's words substituted into it, and for a hook with a `statusMessage` it holds that message. 34.19.0 took the first word of whatever the field held as the hook's name. Ids now name only a script or an executable on PATH, and everything else is a hash. The same report also showed that the timing summary was quadratic, so the 30-day scan now runs in 24 s instead of 41 s and its peak memory dropped from 1.8 GB to about 650 MB.

### Bug Fixes

- **Hook ids no longer carry text that is not a command.** An id is a script's file name, an executable found on PATH under exactly that spelling (checked against the directory listing, because macOS file systems resolve "Make" to `make`), or `inline:<hash>`. Stop entries that carry `promptText` are timed under the single id `prompt-hook`; a word containing `@` or `://` is never an id.
- **Status-message hooks keep their names.** The inventory records each handler's `statusMessage` id, and the scan counts those transcript records under the handler's script, so in the 30-day window the 12,403 runs of the broad process-signal guard, which Claude Code recorded under its status message, count under that guard again instead of under the word "Checking".
- **Untagged messages keep only their leading plain words.** The first word holding a path, an address or a quote ends the tag, so a guard that echoes the refused command no longer leaks part of a path into the tag.
- **The timing summary computes each statistic once.** It had copied the per-event sample array once per tool call and re-sorted every hook's samples inside the sort comparator.
- **A tighter line prefilter** matches only the four record shapes the census reads, and a new `--gc-every` flag (default 50 transcripts) forces a collection between files.
- **Tests:** a case for every text that must not become an id (a prompt, a status message, an inline `if`, a capitalised word, an address, a URL), a prompt-hook Stop entry, a status-message alias in the two-launcher fixture and an echoed path in an untagged message; 19 census tests in all.
- **Docs:** the privacy contract in `plugins/itp-hooks/docs/hook-census.md` defines ids and untagged tags exactly, says how to clean a census directory written by 34.19.0 (rerun `report`), and gives the 30-day resource figures measured with `/usr/bin/time -l` next to the process's own lower reading.
