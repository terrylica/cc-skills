## Narrative

This patch release teaches the disk-hygiene skill what a real audit found when a Mac lost well over 100 GB in nine days without any single runaway file. The old "sudden loss" sweep looked only for huge recent files, and it stalled inside Chrome's per-launch code-sign clones, a folder `du` reported as several TB on a much smaller disk. The skill now has a sweep for slow regrowth, a section on those clones (what they cost, what makes them leak, how to find the launcher and clean up), and corrected advice for agent git worktrees and Aerial wallpapers on macOS. Every number in it was measured with `df` on that machine, which gained over 100 GB of free space.

## Added

- **Slow-regrowth sweep:** Phase 3 sums files over 20 MB written since the last good date, grouped by directory, with Chrome's clone folder and OrbStack's sparse disk image pruned so the scan finishes (#139).
- **Chrome code-sign clones:** a section that explains why only clones of replaced Chrome versions cost space (2,483 clones over 4 old versions freed 4.0 GB), how to spot the live clone by birth time, and a cleanup recipe that runs to completion under `set -euo pipefail` (#139).
- **What leaks a clone:** controlled trials showed that a self-exit, Playwright `close()` and a URL handoff to a running Chrome clean up, that SIGTERM and SIGKILL each leave a clone behind, and that Chrome for Testing makes none. The skill now says how to find the launcher (poll `pgrep`, print each new PID's parent chain) and how to fix it (#139).
- **Quick Wins row for merged agent worktrees:** remove them when clean and merged, checked against the PR's `headRefOid`; dedup the kept LFS-heavy ones (#139).

## Changed

- **Agent-worktree row:** on macOS these checkouts are real files (9 merged worktrees freed 46.8 GB of about 48 GB by `du`). `git lfs dedup` is the cheapest fix that keeps the data (a new 5.71 GB worktree gave back 4.06 GB in one second), and it must never run where `lfs.fetchexclude` keeps pointers on purpose, because it writes them back. The "fully pushed" test now accounts for squash-merged PRs whose branch was deleted (#139).
- **Aerials row:** once the system Aerial store has been emptied, the per-user videos are the only copies, so deleting all but the current wallpaper's frees real space (21 files, 9.7 GB) (#139).

## Fixed

- **Two missing Troubleshooting rows:** `brew cleanup --prune=all` exiting 1 on a root-owned keg still frees space, and scans that stall or report terabytes point at the Chrome clone folder (#139).
