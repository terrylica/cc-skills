## Narrative

This patch makes the Amazon Photos downloader handle links that share a single photo. "Share" on one picture produces a link of exactly the same shape as an album link, but behind it the share's root holds the photo itself instead of an album folder. The script assumed an album, listed the photo's (non-existent) children and reported zero items, so a single-photo link silently downloaded nothing while looking like an empty album. It now recognises the photo node and downloads it directly, with the same size check and manifest as album downloads; album links behave exactly as before.

## Fixed

- **amazon-photos-album-download, single-photo shares:** when the share root's first child is a file rather than a folder, `download-album.ts` downloads that node as the only item instead of listing its children, and logs `file=<id>` in place of `album=<id>`.
- **Album shares unchanged:** a folder child is still listed with the image/video filter, so existing album downloads produce the same files and manifest.
- **Verified on real links:** two single-photo shares that previously reported `total=0` each downloaded 1/1 with the size check passing.

## Changed

- **SKILL.md:** a new gotcha entry explains single-photo shares, how to recognise them in the log, and the old `total=0` symptom.
