## v33.8.0 — 2026-10-05

v33.8.0 does three things. It moves the GitHub web credentials the PAT engine stores into the vault's crown-strict scopes. It stops the release pipeline from relying on two `@semantic-release/github` settings that the plugin has deprecated. And it corrects an assumption about how the commits hook is installed. The PAT engine used to keep each account's passkey, password and TOTP seed with an app-level Touch-ID helper that could be impersonated by re-signing; it now writes them to a crown-strict vault scope encrypted only to the owner's Secure Enclave key, and the devops-tools guidance points crown jewels at those scopes too. The release config replaces `successComment: false` and `failComment: false`, which logged a deprecation warning on every release and are due to stop working at the plugin's next major version, with the documented `successCommentCondition: false` and `failCommentCondition: false`. Finally, the `commit-msg` hook installer turns out to write an exec shim, not a copy as its header claimed, so the hook now sources the shared knob helper instead of carrying its own copy of the alias rule.

### Added

- **PAT engine stores web credentials in crown-strict vault scopes** (`72fa0423`, gh-tools): the `github-web-<account>` blob moves from the retired app-level Touch-ID helper into the crown-strict scope `github-web-<account>`.

### Fixed

- **No more semantic-release deprecation warnings** (`e8567a0f`, #227): `successCommentCondition: false` and `failCommentCondition: false`, documented by the plugin README as "do not create any comments at all", skip the same API calls. `test-iter143` pins the new keys and the absence of the old ones.
- **The commit-msg hook sources the shared knob helper** (`0d7134cb`, #229): installed repositories run the hook in place through an exec shim, so the inline alias fallback that v33.7.0 added was unnecessary. The installer header, hook header and docs now describe the shim, and #226 no longer requires reinstalling hooks before the aliases are removed.

### Documentation

- **Crown jewels go to crown-strict vault scopes** (`69bb141b`, devops-tools): the SCS context hook, the plain-Keychain nudge, `docs/self-custody-secrets.md` and the marker registry point there instead of `vault --gated`.
- **Four measured browser-automation pitfalls** (`eccf24eb`, chrome-profiles): captured one-time credentials, script-set text that frameworks do not persist, custom listboxes, and tab-to-window mapping.
- **Dead `mise run` footnote removed from `docs/RELEASE.md`** (`af9164f6`, #227).

### Verified

- `repo:test-hooks`: 115 of 115 test files; `test-iter143` 11/11; `test-iter157` 14/14.
- All 11 installed `commit-msg` hooks on the release machine are exec shims pointing at this checkout; reinstalling produced identical files.
