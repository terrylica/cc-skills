## [34.13.1](https://github.com/terrylica/cc-skills/compare/v34.13.0...v34.13.1) (2026-11-11)

Orca now opens an agent as a chat tab as well as a terminal, depending on the user's Chat | CLI setting, and two orca-tools skills assumed a terminal everywhere. Run in an Orca chat (Orca 1.4.255), `orca-closeout --close` waited 600 seconds for an idle signal that a chat never sends and reused a stale terminal handle from an earlier tab. `orca-spinoff create` reported a chat it had started successfully as `"terminal": ""` and `"prompt_seen": false`, after warning about missing terminals and waiting 90 seconds for a prompt in a terminal that did not exist. Both skills now read what Orca actually started. A chat is named with `orca chat rename`, and a close that Orca's CLI cannot perform is refused before anything changes. A spin-off reports the chat session and whether Orca accepted its prompt. Both paths were run live against Orca 1.4.256 before release (#66, closes #68).

### Summary

- **session-closeout:** in an Orca chat (`ORCA_STRUCTURED_SESSION` set) the script names the chat with `orca chat rename` and ignores any terminal handle inherited from an earlier tab. A live run renamed the chat and wrote the session name records.
- **session-closeout:** `--close` in a chat is refused up front with exit 2 and changes nothing. Orca's CLI has no command to close a chat (`orca chat` has only `rename`), so the user closes the tab by hand. In the live run the refused close wrote no name record.
- **session-closeout:** the JSON output gains `surface` (`terminal`, `chat`, or null outside Orca). No `[running]` markers are set in a chat, because a chat has no terminal title to restore.
- **worktree-spinoff:** new `--surface terminal|chat`, passed to `orca worktree create` only when given, as Orca's `orca-cli` guide asks. Without it, the user's Chat | CLI setting decides. A chat is refused on an Orca too old for the flag and on a paired runtime.
- **worktree-spinoff:** the result reads `launch.outcome`. A chat is reported with `chat_session`, `agent_handle` and `prompt_outcome`, without the terminal count warning or the 90-second wait. A fallback to a terminal is warned with Orca's own reason.
- **Tests:** session-closeout has 59 tests (8 new for chats), and worktree-spinoff has its first test file. All of them run under stock `/bin/bash` 3.2 with a stub Orca CLI.

### Bug Fixes

* **orca-tools:** spinoff follows the user's Chat | CLI setting ([637fd21](https://github.com/terrylica/cc-skills/commit/637fd21e16b538f5f3e5ab4c0a84b469b4798e29)), closes [#66](https://github.com/terrylica/cc-skills/issues/66) [#68](https://github.com/terrylica/cc-skills/issues/68)
* **orca-tools:** support Orca chat sessions in session-closeout and worktree-spinoff ([b627a2d](https://github.com/terrylica/cc-skills/commit/b627a2dc261b0e3bb2c3e258ec707953131c0daa))

In an Orca chat (ORCA_STRUCTURED_SESSION set) orca-closeout now names the chat with `orca chat rename`, ignores any terminal handle left over from an earlier terminal tab, never marks [running], and refuses --close up front (exit 2), because Orca's CLI has no command to close a chat and a chat never reports tui-idle. Both forms report `surface`.

orca-spinoff create gains --surface terminal|chat (default terminal, passed explicitly when Orca supports it, so the user's Chat | CLI setting cannot silently turn the launch into a chat). It reads result.launch: a structured outcome is reported as a chat (chat_session, agent_handle, prompt_outcome) without the terminal count warning or the 90 s wait for the prompt's title; Orca's fallback to a terminal is warned with its receipt.

Tests: 8 new closeout tests (59 total), first orca-spinoff test file (8 tests).
