## v33.6.0 — 2026-10-04

v33.6.0 makes two pieces of account and settings hygiene deterministic. The gh-tools identity guard now fails closed: for an owner the path-owner registry maps to an account, a `gh` write goes through only when it can be shown to use that account's profile. Separately, the release sync stops filling `~/.claude/backups/` with copies of `settings.json`. Since v20.2.3 the hook sync only removes legacy duplicate hook entries, so on an up-to-date machine every run was a no-op, yet each one copied the file and none of the copies were ever removed: 772 copies (22 MB) built up on one machine between April and October. A no-op run now touches nothing, and a real prune keeps only the newest five copies, sharing one implementation with the command snapshots that already had that cap. The README stops telling new users to sync hooks into `settings.json`, which was the duplicate registration the script exists to undo.

### Added

- **gh-tools identity guard fails closed for registry-known owners** (`98820757`): for a target owner the path-owner registry maps to an account, a `gh` write is allowed only through the routing shim (`~/.local/bin/gh`) with `~/.config/gh-<account>` present; a missing shim, a missing profile or an absolute-path `gh` binary is denied. No network and no `gh` call in the decision. Escape: `ALLOW_OWNER_MISMATCH=1`. Adds `accountForOwner()` to the registry library, with a 6-case regression test on a synthetic `HOME`.

### Fixed

- **`sync-hooks-to-settings.sh` copies `settings.json` only when it prunes** (`01177df2`, closes #218): with nothing to prune it returns before copying or rewriting the file, which Claude Code itself also writes.
- **Backups stay bounded** (`01177df2`): `scripts/lib/backup-retention.sh` is now the one home for `CC_SKILLS_BACKUP_RETENTION` (default 5). Both sync scripts use it, with a timestamp-only name pattern that never matches files a person parked in `backups/`.

### Documentation

- **README describes how hooks actually load** (`502b8226`): plugin hooks come from each plugin's `hooks/hooks.json`; the sync script is a one-time cleanup for pre-v20.2.3 installs; registered hooks are checked with Claude Code's `/hooks` menu, which labels each hook's source.

### Verified

- Against the same fixture `HOME`, the v33.5.4 script makes one `settings.json` copy on a no-op run and this release makes none.
- `tasks/tests/test-sync-backup-retention.sh` (4 cases) and the existing `test-sync-hooks-prune-malformed-settings.sh` pass; `moon run repo:check` passes (2233 tests across 86 files).
