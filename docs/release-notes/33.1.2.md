## v33.1.2 — 2026-10-01

v33.1.2 fixes one latent hook bug and removes a dead tool name. The Write/Edit PreToolUse orchestrator used to exit 2 for both deny and ask. Exit 2 always blocks, so any subhook's "ask" would have hard-blocked the edit instead of prompting, and the first ask also skipped any later deny. Both decisions are now the documented JSON with exit 0, an ask waits for the remaining subhooks, and a later deny wins. MultiEdit is no longer a Claude Code tool, yet 88 files and a push-gate audit still required it in every file-edit matcher; it is retired. The Stop-hook docs now match current upstream: Stop accepts `additionalContext`, but it keeps the conversation going, so informational summaries still go to stderr. 31 scripts and hook modules with names of up to 247 characters now have names of at most 51, and the commit-msg hooks installed from them were reinstalled.

### Fixed

- **Write/Edit orchestrator decisions** (#199, #200): deny and ask are both emitted as `hookSpecificOutput.permissionDecision` JSON with exit 0, and stdout is drained before exit.
  - An ask now prompts instead of blocking. This was latent: the vale CLAUDE.md guard, the only subhook that can ask, runs in deny mode.
  - An ask is held while the remaining subhooks run, so a later deny wins: deny > ask > allow, the precedence Claude Code documents.
  - Deny still blocks, now with exit 0. The old exit 2 was a workaround for anthropics/claude-code#37210, which was closed as not planned after its reporter found their own hook's exit 2 was the cause.
  - A new 10-case test covers ask, deny, deny-after-ask and the real orchestrator, and the iter-84 to iter-90 suites now expect exit 0.
- **Stop-hook docs and comments** (#201, #202): `stop-hooks.md` now records what Stop, SubagentStop, PreCompact, SessionEnd and Notification each do with hook output, per the current hooks reference. It lists the four real Stop subhooks, and it drops a reference to a guard that does not exist. The Stop audit's stated reason now cites upstream; what it detects is unchanged.
- **Orchestrator docs** (#202): the PreToolUse spoke said 8 subhooks (the registry has 11), the PostToolUse spoke said "7/15" (it has 12), and the itp-hooks hub said "all 8".
- **ssh-tunnel-companion** (6d6e8296): the Tailscale CLI is resolved instead of hard-coding the macOS app's helper path.

### Removed

- **MultiEdit as a live tool name** (#201, #202): `Write|Edit|MultiEdit` matchers in itp-hooks, dotfiles-tools and rust-tools become `Write|Edit`. Tool-name allow-sets and classifier branches drop it too.
  - `tasks/hook-lint/matcher-multiedit.sh` is deleted, along with its preflight check, its batch record and its escape marker.
  - Two tests that existed only for MultiEdit are deleted. A third (iter-102) now asserts the allow-set is exactly Write and Edit.

### Changed

- **31 long names shortened** (#203, #204): 16 scripts, 4 `scripts/lib` helpers, 9 `hooks/lib` modules, a triage task and the two orchestrators, now `pretooluse-write-edit-orchestrator.ts` and `posttooluse-write-edit-orchestrator.ts`.
  - Every reference was updated: imports, `hooks.json`, `moon.yml`, tests, docs, `cli_spec.json` and `.pre-commit-hooks.yaml`. Its `entry:` is now `scripts/iter158-pre-commit-entry-point.sh`; consumers pinned to a `rev:` are unaffected.
  - The iter-104 test no longer imports from a hard-coded main-checkout path.
- **Installed commit-msg hooks:** the installed shim calls the hook script by absolute path, so it was reinstalled in the 11 local repos that had it. If you installed it elsewhere, run the installer again: `moon run repo:commits-install-hook` inside cc-skills, or `scripts/iter157-commit-msg-hook-installer.sh install` from the target repo.
