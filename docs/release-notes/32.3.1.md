## v32.3.1 — 2026-09-27

v32.3.1 finishes retiring Claude Code's kernel sandbox from cc-skills. The operator ruled on 2026-09-27 that the sandbox blocked too much autonomous work, and the managed sandbox policy was uninstalled that afternoon from all four hosts it had been installed on; this release removes the policy from the repository itself — installer, escape gate, session check, diagnostics broker, `host-notes` and verifier — and puts `draft-park` back on its single `osascript` path. Everything removed is recoverable from the tag `archive/pre-retire-managed-sandbox-policy`. The kill guards are ordinary plugin hooks and are unaffected.

Reviewing that revert turned up something more important than the revert: several ways notes-commander could fail silently or lose work, most of them older than the sandbox work. The worst could delete the only real copy of a draft — `draft-park new` removed every other same-title note even when it could not see the note it had just created. Others printed or copied an empty draft with exit 0, accepted text silently truncated past about 1 MiB, or let one unconvertible note abort a whole `notes export` backup before its manifest was written. Each now fails loudly or is contained: unit tests cover the self-heal guard, the unreadable-body check, the numeric `&#160;` case and a 2 MB text conversion, and the new exit 2 from `get`, `list` and `new` was checked live.

### Removed

- `plugins/itp-hooks/managed-sandbox-policy/` and its spoke `docs/managed-sandbox-policy.md`, the `repo:sandbox-policy-verify` moon task, and their CLAUDE.md and spoke-index rows; the root CLI count drops from 40 to 37 ([b0ce32d](https://github.com/terrylica/cc-skills/commit/b0ce32d786395fe52421fb8cbdeecd4789192d2e)).
- `draft-park`'s broker backend: `pickBackend`, `DRAFT_PARK_BACKEND` and the `host-notes` branch of `htmlToText()` ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).

### Added

- `draft-park new --allow-empty` parks a title-only note on purpose; without it an empty stdin is refused ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- `sandboxHint()`: when `SANDBOX_RUNTIME` is set, a failed Notes call says it is running inside Claude Code's sandbox instead of ending on a bare `-10810`, and a failed text conversion says the same instead of pointing at the deleted installer ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- `docs/release-notes/32.3.0.md`, the stored narrative for v32.3.0 ([91aab43](https://github.com/terrylica/cc-skills/commit/91aab43ee49d000509d46e799df10db4edcd2fdb)).

### Fixed

- `draft-park new` self-heal deletes older same-title copies only once the new note is listed in the folder, so it can no longer delete the only real copy ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- Notes reads and text conversion no longer accept truncated output: Bun's default `spawnSync` buffer returned status 0 with `ENOBUFS` past about 1 MiB, and both paths now allow 256 MiB and treat that error as a failure ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- `notes export` skips a note whose text conversion fails, with a `⚠` line and exit 3, instead of aborting before `manifest.json` ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- `draft-park get`/`sticky` on a missing title exit 2 with `✗ no draft titled …`; an empty or `missing value` body fails as `READ-FAILED`; `get --body-only`/`--copy` refuse to emit empty text ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).
- `draft-park list --folder <missing>` exits 2, `sticky` stops on a failed `pbcopy` instead of pasting the previous clipboard, and a numeric `&#160;` no longer counts as visible text ([dbc5912](https://github.com/terrylica/cc-skills/commit/dbc591213cb51dac90b7a05cb699e69a0aa0ca35)).

### Upgrade notes

- A host that still has the managed sandbox policy installed must remove it with the installer from the v32.3.0 tag, since this release deletes it: `git show v32.3.0:plugins/itp-hooks/managed-sandbox-policy/install_managed_sandbox_policy.py > /tmp/install_managed_sandbox_policy.py && sudo /usr/bin/python3 /tmp/install_managed_sandbox_policy.py --uninstall --apply`, then restart every open Claude Code session.
- Scripts that call `draft-park` should expect the new non-zero exits: 2 for a missing title, a missing folder in `list`, an unreadable body, empty sendable text, an empty `new` body or a failed `pbcopy` in `sticky`. Previously most of these exited 0 after printing nothing, a `(no such draft)` or `(folder not found: …)` placeholder, or, for an empty `new`, the id of a title-only note.
- `DRAFT_PARK_BACKEND` is no longer read; setting it has no effect.
- `notes export` now writes `manifest.json` and exits 3 when a note's text conversion fails, where it used to crash with exit 1 and no manifest; in this release the skipped note is named only in the `⚠ note skipped` lines, not in the manifest, so a script that treats an existing `manifest.json` as a complete backup must also check for exit 3.
