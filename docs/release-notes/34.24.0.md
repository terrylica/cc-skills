## Narrative

This release makes the Braille Tally the start of every GitHub issue title an agent writes, the same convention the AskUserQuestion guard already holds for option labels. A reader scanning an issue list now sees at a glance how each issue was assessed, on Importance · Urgency · Simplicity, in the same word-sized shape used in questions and ranked lists: the title is the tally, one space, then the text, the glyph alone, for example `⣿⣶⣴ Fix the login timeout`. A new PreToolUse guard in the `braille-tally` plugin enforces it before an issue is created or retitled, whichever way the agent does it (the `gh` CLI, the REST or GraphQL API, a shell script it writes for later, or a GitHub MCP server), and gh-tools' existing title reminder now says the same. One review round by a different vendor's model found twelve realistic misreads in the first draft, from `echo gh …` being taken for a command to a title hidden inside `$( … )`; each is fixed and pinned by a test.

## Added

- **Issue-title guard** (`plugins/braille-tally/hooks/issue-title-tally-guard.ts`, matcher `Bash|Write|Edit` and GitHub MCP issue tools): denies a literal issue title that does not start with a tally and one space, that puts digit levels or a number after the tally, or that uses Braille cells which are not tally levels. It names the exact fix, never repairs, fails open on anything unexpected and makes no network calls (#134).
- **What it reads:** `gh issue create|new|edit` with every `--title` form, also after `--repo`, inside `$( … )`, backticks and heredocs fed to a shell; `gh api` on `repos/OWNER/REPO/issues[/N]` with a `title` field (not GET); `gh api graphql` `createIssue`/`updateIssue`, literal or through the variable's field; shell scripts being written or edited, judged by the titles the change adds; GitHub MCP `create_issue`, `update_issue` and `issue_write` (#134).
- **26 tests** in `plugins/braille-tally/tests/issue-title.test.ts`, 12 of them from the review round; a 1 MB script is checked in about 50 ms (#134).

## Changed

- **gh-tools title reminder:** `gh-issue-title-reminder.mjs` names the tally in both of its reminders, so the reminder and the guard say the same thing (#134).
- **Docs:** the `braille-tally` skill (rule 5, a guard section, the evolution log), both plugins' CLAUDE.md, the plugin README, `plugins/CLAUDE.md`, the root README and the marketplace description describe the convention, in general terms (#134).

## Known limits

- A JSON body sent with `gh api --input` is not read, and a title built from a variable is allowed (only its known prefix is checked).
