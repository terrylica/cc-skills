## Narrative

This patch adds one hard-won rule to the browser-automation skill. Uploading a file through the Playwright Extension with Playwright's `setInputFiles` never completes: every attempt timed out, and one coincided with the operator's Chrome going unresponsive until the run was stopped. Building the `File` inside the page and handing it to the input through a `DataTransfer` works, and upload widgets built on that input accept it. The skill now says so next to its existing advice on setting form values by script, so the next session can upload a document without freezing a signed-in browser.

## Fixed

- **chrome-profiles, browser-automation:** a new bullet records the `setInputFiles` hang through the Playwright Extension (measured 2026-11-26).
- **The working route:** rebuild the `File` from base64 bytes in the page, assign it to the `input[type=file]` with a `DataTransfer`, and dispatch `change`.
- **Handling the bytes:** pass them in a step marked `quiet` so the run does not echo them, and delete the steps file afterwards.
- **Multi-file forms:** a drop zone often becomes a preview after its upload, so query the file inputs again before the next one.
