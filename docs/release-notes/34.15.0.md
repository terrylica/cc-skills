## [34.15.0](https://github.com/terrylica/cc-skills/compare/v34.14.1...v34.15.0) (2026-11-14)

This minor release lets every long-running Pushover sender have its own application. `pushover_core.ts` knew two apps, `main` and `test`, and quietly sent every other name to the test app. So any job that named no app, or a dedicated one, landed in the test channel, and real alerts (Telegram replies waiting to be read, pipeline breaks, update outcomes) sat mixed in with self-test noise. `--app <name>` now reads the token stored as `api_token_<name>`, wherever the resolver finds it first, so a new app needs a stored token and no code change. The name is checked strictly before anything is sent, because it now selects a credential field.

### Summary

- **pushover-commander:** `--app <name>` sends through a dedicated application whose token is stored as `api_token_<name>` (self-custody vault scope, 1Password label or Keychain account) ([#84](https://github.com/terrylica/cc-skills/pull/84)).
- **pushover-commander:** `main` and `test` keep their fields (`api_token_main`, `api_token_test`), so existing callers are unchanged; `test` stays the default.
- **pushover-commander:** names are 1 to 40 lower-case letters, digits or underscores, so a name cannot reach another credential field or the shell; anything else is refused before a request is sent.
- **pushover-commander:** the mapping is the exported pure function `tokenFieldFor`, covered by `pushover_core.test.ts` (built-in apps, dedicated apps, and seven refused names).
- **pushover-commander:** `send-notification`, `emergency-priority2-receipt`, `custom-sounds`, the resolver's header, the example env file and the private-config reference document the new form.

### Features

- **pushover-commander:** `--app <name>` uses `api_token_<name>` ([49e2db9](https://github.com/terrylica/cc-skills/commit/49e2db97b8313d3f5108fe62d5418fa0f454a581))

`pushover_core.ts` knew two apps: `main`, and `test` for everything else. So every long-running sender that named no app, or any app other than `main`, went out through the test app, and alerts from unrelated jobs piled up in one test channel. `--app <name>` now reads the token stored as `api_token_<name>` (vault scope, 1Password label or Keychain account, whichever the resolver finds first), so each long-running sender can have its own app without a code change. `main` and `test` keep their fields.

Names are lower-case letters, digits and underscores (1-40), so a name cannot reach another credential field or the shell; anything else is refused before a request is sent.

### Verification

- Preflight for this release: 116 hook regression test files and 3,121 Bun unit tests, all passing.
- A real send through a dedicated app returned `status: 1`; a malformed name was refused before any request.
